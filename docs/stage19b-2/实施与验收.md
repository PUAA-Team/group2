## 完成范围

### 1. 训练数据流式读取
- [training_data.py](../../worker/src/training_worker/training_data.py) 新增 `iter_rows(spec)` 生成器：文本分类按行迭代 CSV、LLM SFT 按行解析 JSONL，不再一次性读入并解码整个数据集文件；图像任务流式读 `labels.csv`（`archive.open` + `TextIOWrapper` 逐行迭代，读取中交错取图已验证可行），每行只保存原始压缩字节。
- 图像像素改为按需解码：新增 `row_pixels(row)`，首次使用时才把 `image_bytes` 解码为 32×32×3 像素列表并缓存到行内，同时释放原始字节；[classification.py](../../worker/src/training_worker/classification.py) 的 `tensors()` 改为经 `row_pixels()` 取像素。`read_rows()` 保留为 `list(iter_rows(spec))`，供 `split_rows` / `qwen.py` 等调用方沿用。
- 词表构建改为逐行累计：`Classifier.train()` 不再把全部训练文本拼成一个大字符串，改为 `Counter.update(row["text"][:4096])` 逐行累计后取前 2048 词。

### 2. 单样本/空验证集零分母防护
- `split_rows()`：空数据集直接报 `ValueError("数据集为空，无法划分训练集与验证集")`；非分类任务单样本时全进训练集、验证集为空（原逻辑会分出空训练集，随后在 `total / len(train)` 触发除零）；分类任务单样本仍按原规则报“每类至少需要两条已标注样本”。
- `scores()`：标签为空时直接返回准确率与 Macro-F1 均为 0（原 `sum(f1) / len(f1)` 会除零）；空验证集时准确率已由 `max(1, len(expected))` 保护，返回 0.0。
- `Classifier.train()`：训练集为空报 `ValueError`；验证集为空时跳过验证前向与 `CrossEntropyLoss` 计算，`val_loss` / `val_accuracy` 置 0.0，`scores()` 以空预测计分，不触发除零。`qwen.py` 的 `Qwen.train()` 同样加训练集为空保护；其 `validation()` 本就以 `max(1, tokens)` 保护，空验证集返回 `(0.0, 0)`。

### 3. 说明与边界
- 本阶段无表结构变更，无 Alembic 迁移；无新增 API 接口，OpenAPI 同步导出到 [openapi.json](./openapi.json)（144 个路径，与上一阶段一致）。
- 残留边界：`read_rows()` 取列表时图像原始压缩字节仍会全部驻留内存（已比原来整套 `list[int]` 像素小一个量级，单图约 3072 个 Python 整数）；如需彻底按批流式训练，需后续把 `train()` 改为按批从生成器取数。
- `classification.py` / `qwen.py` 的训练主流程依赖 torch，本机 `.venv` 未安装 torch（与此前各阶段一致），上述两文件的改动以 `py_compile` 与新增纯函数测试覆盖，未在本机实际跑通一次真实训练。
