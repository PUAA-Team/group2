# Stage 20A-2：前端 live/ 结构解耦与安全升级

分支：`lx/stage20a-2-live-decoupling`（基线 `lx/stage20a-1-password-reset`，本地 b90b748，未合并 main，未部署，未推送）。

## 完成范围

### 1. live/ 与原型目录解耦

- 新建 [frontend/live/ui/](../../frontend/live/ui/)：把 live 真正需要的通用原语从 `frontend/js/ui.js`（8765 原型）内聚迁移过来——`shell`、`NAV_GROUPS`、`ADMIN_NAV`、`badge`、`icon`、`escapeHtml`、`linkButton`、`card`、`pageHeader`、`emptyState`、`lineChart`（[ui.js](../../frontend/live/ui/ui.js)，与原型文件内容一致）；`installStatusTooltip` 从 `frontend/js/status-tooltip.js` 迁移到 [status-tooltip.js](../../frontend/live/ui/status-tooltip.js)。
- [app.js](../../frontend/live/app.js)、[components.js](../../frontend/live/components.js)、[preferences.js](../../frontend/live/preferences.js) 改为从 `./ui/` 导入；live/ 内已无任何 `../js/` 引用（新增测试断言）。
- `frontend/js/` 与 `frontend/design-review/` 仍保留：生产入口是 `frontend/live/index.html`，不再引用它们；`frontend/index.html`（8765 原型入口）仍引用 `./js/app.js`，原型对照用途不变，未删除。

### 2. 缓存版本标识统一为单一构建常量

- 新增 [live/ui/version.js](../../frontend/live/ui/version.js)：`ASSET_VERSION = "stage20a-2"`。
- live/ 内全部 101 处 `?v=`（模块 import 与 `live/index.html` 的样式/入口引用，原先混用 `console-4`、`stage15-1`、`stage16-local`）统一为 `?v=stage20a-2`。原型入口 `frontend/index.html` 仍用 `console-4`，不在本次统一范围内。
- 新增测试：逐文件扫描 live/ 的 `?v=`，断言与 `ASSET_VERSION` 完全一致；改动 live/ 任一模块后同步更新该常量即可。

### 3. 事件与对话框分发改为显式路由表

- [events.js](../../frontend/live/events.js)：点击分发拆为两张表——`clickPipeline`（按顺序试各功能模块的 `*Action` 处理器，命中即停；`admin-test-connection` 保留调用前后禁用/恢复按钮的特殊处理，位置仍在 `administrationAction` 之前）与 `clickActions`（`Map<action, handler>`，覆盖原先 25 个行内 `if (action === ...)` 分支：`toggle-password`、`toggle-nav`、`collapse-sidebar`、`open-menu`/`close-menu`、`logout`、`refresh`、`go`、`modal`、`close-modal`、`edit-asset`、`edit-group`、`edit-user`、`edit-member`、`toggle-user`、`page`、`clear-search`、`template`、`select-workspace`、`preview`、`dataset-report`、`session-revoke`、`session-revoke-others`、`admin-job-stop`、`admin-job-retry`）。分发逻辑不变：未知动作不处理、异常仍由外层 `try/catch`  toast。
- [dialogs.js](../../frontend/live/dialogs.js)：`projectDialog(modal) || keyDialog(modal) || ...` 的 `||` 串联改为 `DIALOG_RENDERERS`（`Map<kind, renderer>`，共 50 个 kind 到 10 个渲染函数的映射，含 `assistant-*` 三个新建请求 kind 与 `connection-new/edit`、`group-members` 等）。`renderDialog` 先查表、再走原有的按 kind 的字段分支（`workspace-new`、`model-new`、`member`、`group-new`、`user-new` 等与路由表无重叠）；未知 kind 仍渲染空标题弹窗，与旧行为一致。
- 新增测试：路由表覆盖的 6 个 kind（`project-new`、`project-archive`、`gov-archive`、`job-stop`、`data-cancel`、`keys-expiry`）渲染标题正确，未知 kind 不抛错。

### 4. table() 默认转义单元格，raw() 标记受信任片段

- [components.js](../../frontend/live/components.js)：新增 `raw(html)`（返回 `{ __rawHtml: true, html }` 标记对象）与内部 `cellHtml()`；`table()` 的单元格默认走 `e(cell)` 转义，只有 `raw()` 包裹的片段原样输出；表头仍显式转义。
- 17 个调用点文件同步迁移（`live/pages/admin.js`、`live/pages/assets.js`、`live/pages/overview.js`、`live/admin-workflows.js`、`live/administration.js`、`live/assistant.js`、`live/catalog.js`、`live/compute.js`、`live/data-workflows.js`、`live/dataset-import.js`、`live/dialogs.js`、`live/job-detail.js`、`live/key-management.js`、`live/parameter-templates.js`、`live/projects.js`、`live/results.js`、`live/workflows.js`）：纯文本/数字单元格去掉多余的 `e()`（由 `table()` 转义，避免双重转义）；`badge`/`tag`/`link`/`btn` 及 `<span>`/`<div>`/`<img>`/`<input>` 等 HTML 片段改为 `raw(...)` 包裹；`fieldsInfo` 未动（本阶段范围只含 `table()`）。
- 新增测试：`<script>` 注入被转义、`raw(badge(...))` 正常渲染、`raw(e(...))` 不双重转义、数字单元格正常渲染、表头转义。

### 5. 说明与边界

- 本阶段纯前端，无后端改动、无表结构变更、无新增接口；OpenAPI 同步导出到 [openapi.json](./openapi.json)（146 个路径，与上一阶段一致）。
- `frontend/js/ui.js` 与 `frontend/js/status-tooltip.js` 仍保留供原型入口使用，live/ 与原型各有一份拷贝；后续若原型下线，可直接删除 `frontend/js/` 与 `frontend/design-review/`。
- `raw()` 只用于本仓库代码生成的受信任片段（`badge`/`tag`/`link`/`btn` 及内部模板），不得用于包裹未经转义的用户输入；`objectLink` 返回的 `e(...)` 文本包在 `raw()` 里仍是已转义文本，不会二次转义。
