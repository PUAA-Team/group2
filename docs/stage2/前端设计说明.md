# 第二阶段前端设计说明

## 目标与边界

本阶段把平台扩展为可演示的用户端与管理端。登录、数据准备、模型训练、评估、服务发布、用户权限及计算资源接入均可在浏览器内走通界面流程。页面不连接后端、训练集群或推理服务；所有设备状态、指标、接入结果与调用响应都是演示数据。

设计延续第一阶段的固定侧栏、灰白底色与蓝色主操作。侧栏在桌面以 256px 展开，可收至 68px；1024px 以下改为抽屉。导航按二级分组，管理员入口位于分隔线下方。普通用户不显示管理入口，直接访问管理地址也会看到无权访问页面。

## 信息架构

| 一级菜单 | 二级页面 | 页面要点 |
| --- | --- | --- |
| 概览 | 工作台、用户空间、资源监控 | 任务摘要、个人有效权限、资源与队列状态 |
| 数据管理 | 数据集、在线标注、数据增强 | 数据模板、版本处理、标注批次、增强策略 |
| 模型训练 | 训练项目、训练任务 | 项目内多次训练、四步配置、指标与日志 |
| 模型管理 | 模型仓库、模型评估 | 预置模型、网络结构、训练产物、同类任务对比 |
| 部署服务 | 在线服务、API KEY管理 | 服务创建与测试、演示密钥生成和停用 |

管理端设统计面板、资源管理、数据管理、模型管理、作业管理、用户管理、操作记录和系统设置八个一级入口。业务管理页提供全平台视角，用户端相关详情页仍保留原有深入操作入口。

页面组织参考[飞桨 BML 调研](<../调研结果/飞帆BML 全功能AI开发平台调研报告.md>)及[补充笔记](<../调研结果/调研(2).md>)的数据准备、项目训练和模型发布流程；资产版本与评估参考[Azure 调研](<../调研结果/Azure调研报告.md>)；用户空间、资源和作业视角参考[Crater](<../调研结果/Crater.md>)与[Kubeflow](<../调研结果/Kubeflow 调研.md>)。具体交互以当前平台的任务目录和前端演示能力为准。

## 关键流程

### 登录与身份

登录页提供管理员和普通用户演示入口，也允许用户自主注册。注册用户进入普通用户空间。演示账号用于快速切换视角；新注册账号的密码摘要保存在浏览器本地，当前会话标识保存在会话存储。该机制只用于前端流程验证，不能承担真实身份认证和安全授权。

### 数据与训练

数据集按图像、文本、表格、大语言模型分组。导入时选任务、查格式、下载模板，并在详情页模拟处理及版本更新。在线标注可以登记标签批次；数据增强按数据类别过滤策略。两者都只保存配置与演示记录，不生成真实标注文件或增强样本。

训练继续采用“任务与模型 → 数据集 → 参数与资源 → 核对提交”。文本分类增加 Qwen2.5-0.5B-Instruct 预置模型，指令微调增加独立任务，提供 LoRA、训练轮次、批大小、学习率、序列长度等配置项。分类路径将标签视作指令输出；当前 CSV 与指令样本的转换尚未实现。模型名称与性质参考[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct)，微调方式参考[Qwen 官方训练文档](https://qwen.readthedocs.io/en/v3.0/training/llama_factory.html)。页面不对显存需求或训练结果作真实性承诺。

### 权限与配额

用户组提供基础授权；个人权限可设为继承、允许、禁用。有效权限先合并组授权和个人允许，再扣除个人禁用，因此显式禁用优先。GPU 与并发任务有效上限分别取组上限和个人上限的较小值。用户管理页同时提供成员状态、组创建、组授权与个人配置。导航可见性和页面路由按演示身份判断，真正的服务端权限校验列入后续开发。

### GPU 节点接入

资源管理分为设备、计算节点、接入新节点。接入页可复制一条带占位地址和令牌的示意命令，登记服务器别名与演示硬件配置，再模拟自动探测，使节点从“待探测”进入“已接入”。命令中的 `agentctl`、平台地址和令牌都是占位内容，**不可在真实服务器执行**。正式接入需要后端签发一次性令牌、提供可信代理安装包、进行双向身份验证、采集硬件信息并经管理员审核。具体安全与运维方案须在后端阶段确认。

## 视觉与实现

登录页采用深蓝灰侧区与白色表单区，业务页延续灰白工作台；两者共用蓝色主操作和紧凑圆角。二级菜单可展开收起，收窄侧栏保留图标与悬停标题。表格只在自身容器滚动，卡片网格随屏宽降列。已检查的 1280px、768px 和 390px 视口没有页面级横向溢出。

实现继续使用原生 JavaScript 模块和 CSS，无新增前端依赖。`js/data.js` 定义任务及种子数据，`js/state.js` 维护本地演示状态，`js/auth.js` 负责演示登录，`js/ui.js` 提供布局，`js/pages/` 按页面分离。待完成的真实能力集中列在[后续功能待办](../后续功能待办.md)。
