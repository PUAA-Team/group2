# Stage 20B-1：网关、数据库与容器运行时安全加固

分支：`lx/stage20b-1-deploy-hardening`（基线 `lx/stage20a-2-live-decoupling`，本地 71750da，未合并 main，未部署，未推送）。

## 完成范围

### 1. 网关与数据库容器能力收紧（[compose.yaml](../../deploy/server/compose.yaml)）

- `db` 与 `gateway` 新增 `cap_drop: [ALL]` + `security_opt: [no-new-privileges:true]`；api/migrate/operations 原先已通过 `x-control` 锚点具备这两项，本轮未动。
- `db`/`gateway` 按需保留最小能力 `cap_add: [CHOWN, DAC_OVERRIDE, SETGID, SETUID]`：官方 postgres 镜像入口需 chown 数据目录并以 gosu 切到 postgres 用户；nginx 以 root 启动 master 再 setuid 到 nginx 用户。5432/8080 均大于 1024，不需要 `NET_BIND_SERVICE`。
- `gateway` 新增 healthcheck：容器内 `wget -q -T 5 http://127.0.0.1:8080/readyz`（alpine 镜像只有 wget，没有 curl），经网关本身探测反代链路；无服务依赖网关，api 异常时只影响网关自身健康状态，不会级联停掉其他服务。
- 镜像固定：`nginx:stable-alpine` → `nginx:1.30.8-alpine`（2026-11-23 发布的稳定版），`postgres:17-bookworm` 本就固定；全文件无 `:latest`。

### 2. Nginx 安全响应头与模板化（nginx-*.conf → nginx-*.conf.template）

- 两份配置改为 `.template`，由官方 nginx 镜像入口在容器启动时经 envsubst 渲染；compose 把所选模板挂到 `/etc/nginx/templates/default.conf.template`，并把 `TLS_IP` 传入网关容器环境。
- 统一加：`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: strict-origin-when-cross-origin`、CSP；HTTPS 模板另加 `Strict-Transport-Security: max-age=31536000; includeSubDomains`（HTTP 模板不加 HSTS）。
- CSP：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'`。能收这么紧是因为前端无内联 `<script>`、无内联事件处理器、全部浏览器请求都走同源 `/api/v1`（见 [api.js](../../frontend/live/api.js)）、无外部字体/图片；`style-src` 保留 `'unsafe-inline'` 是因为 JS 模板里有少量 `style="..."` 行内样式（图表图例等），见残留边界。
- 证书路径改用 `${TLS_IP}`，不再写死旧 IP；模板里的 `$http_host`/`$remote_addr`/`$scheme` 不会被 envsubst 替换（镜像入口只替换环境变量表里的变量），已用脚本模拟渲染验证。

### 5. 备份修正与恢复脚本（[backup.sh](../../deploy/server/backup.sh) / [restore.sh](../../deploy/server/restore.sh)）

- **修了一个真 bug**：旧 `backup.sh` 在 db 容器内用 `pg_dump -U "${POSTGRES_USER:-model_platform}" -Fc "${POSTGRES_DB:-model_platform}"`，而容器内 `POSTGRES_USER`/`POSTGRES_DB` 是 `postgres`（维护库），展开后实际备份的是 `postgres` 维护库，不是应用库。已改为显式 `pg_dump -U postgres -Fc -d model_platform`（容器内本地连接为 trust 认证，与旧脚本假设一致）。
- `backup.sh` 新增清单：`tables.txt`（public schema 各表精确行数）、`backup.json`（创建时间、数据库、dump SHA-256 与大小、存储文件数与字节数）；备份后校验 dump 非空、存储归档 `tar -tzf` 可读；保留最近 7 份。支持 `--root`/`--help`，保留位置参数兼容。
- 新建 `restore.sh`：`--backup-dir`（必填）`--root` `--yes` `--skip-verify`。先校验 dump 摘要，确认后停 `api`/`operations`，确保 `model_platform` 角色与库存在，`pg_restore --clean --if-exists --exit-on-error` 从标准输入恢复（PostgreSQL 17 文档确认未指定文件名时读标准输入），恢复 storage（原目录移走加时间戳备份），再逐表比对行数、比对存储文件数，全部通过后才 `up -d api operations` 重启；校验失败时服务保持停止并明确报错。旧格式备份（无 `tables.txt`）须加 `--skip-verify`。
- 新增 systemd 单元 [model-platform-backup.service](../../deploy/server/model-platform-backup.service) / [model-platform-backup.timer](../../deploy/server/model-platform-backup.timer)：每日 `03:00:00` 执行备份（`RandomizedDelaySec=600`、`Persistent=true`，与证书定时器同款）。

- 参数化与续期：`.env.example` 含 `PUBLIC_HOST`/`TLS_IP` 且无旧 IP；`CERTBOT_IMAGE` 固定值；`resolve_tls_ip()` 的命令行/环境变量优先级；缺地址时 `renew()` 明确报错；证书服务用 `${TLS_IP}`。
- 备份/恢复：`backup.sh` 备份应用库而非维护库、`bash -n` 与 `--help`；`restore.sh` 参数校验；`verify_counts`/`verify_storage` 的通过与三类失败（行数不一致、缺表、多表）；摘要提取回归（`grep -o '[0-9a-f]*'` 会把 `dump_sha256` 里的十六进制字母当成片段，演练中真实踩中，已改定长 `{64}` 提取并加测试锁定）。
- 现网文件无旧 IP、旧 `.conf` 文件已不存在、备份定时器为每日 03:00。

## 演练结果（本地桩演练，非真实 PostgreSQL）

本机无 Docker、线上 VPS 不可动，本轮无法在真实 PostgreSQL 栈上演练。改用 `docker` 命令桩（在 `/tmp/mt-rehearsal`）演练了备份→恢复全流程的编排逻辑：

- 备份：生成 `database.dump`、`tables.txt`（jobs 0、users 3）、`backup.json`（含正确 SHA-256）、`storage.tar.gz`，清单内容与桩返回一致。
- 恢复：先破坏 storage（删 `b.txt`、加 `extra.txt`），恢复后 storage 回到备份状态（`a.txt` + `b.txt`），原目录移为 `storage.bak.<时间戳>`，逐表行数与存储文件数校验通过，服务重启；二次恢复幂等通过。
- 拒绝路径：篡改 dump 后摘要不符，恢复在停服务前拒绝（exit 1）；无 `--yes` 且非交互时拒绝（exit 1）。
- **待办**：在预发环境用真实 PostgreSQL 17 跑一次完整备份与恢复（需一台能跑 Docker 的预发机，不动线上生产数据）。

## 说明与边界

- 本阶段纯部署配置与脚本，无后端/前端业务代码改动，无表结构变更，无新增接口。未合并 main，未部署，未推送。
- `db`/`gateway` 未加 `read_only: true`：postgres 需写 `/var/run/postgresql` 与数据卷、nginx 需写缓存与 pid，直接只读会启动失败；如后续要加，需配 `tmpfs`（`/var/run/postgresql`、`/tmp`、`/var/cache/nginx`、`/var/run`）并在预发环境实测。
- CSP 的 `style-src 'unsafe-inline'` 是过渡方案：前端 `compute.js`/`governance.js`/`workflows.js` 的 JS 模板里有 `style="--line:..."` 等行内样式；后续把这几处迁到 CSS 类后可去掉 `'unsafe-inline'`。
- `gateway` 健康检查探 `/readyz` 依赖 api 健康：网关启动时 api 已健康；api 异常时网关健康状态随之变差，但无服务依赖网关，不会级联。
- 备份定时器与恢复脚本只在下次部署到服务器后生效；部署前需在服务器上 `systemctl enable --now model-platform-backup.timer`，并按“演练结果”在预发环境先跑一次真实恢复。
- 证书服务 `EnvironmentFile` 用了 `-` 前缀：`.env` 不存在时不硬失败，续期脚本会在 `TLS_IP` 为空时明确报错。
