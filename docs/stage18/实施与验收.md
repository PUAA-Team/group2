# Stage 18B：状态机与并发加固、多端会话管理与管理端行内操作

## 完成范围

### 1. 状态机、租约回收与并发安全加固
- **过期租约自动回收**：[scheduler.py](../../backend/src/model_platform/services/scheduler.py) 新增 `reclaim_expired_leases(db, node_id=None)`，在节点 `claim` 入口自动回收 `lease_until < now` 的未结案执行，原子将超时的 `Execution` 与 `Job` 标记为 `failed`（`执行租约超时，Worker 已失联`），释放 `ComputeDevice.reserved_execution_id` 及对应待处理的 `ServiceCall`。
- **重投递门禁**：节点断网恢复重投递保留正常恢复通道，同时校验 `Job.status` 必须处于运行/停止中态且未过期，已终态的任务不再重投递。
- **执行结案源状态白名单**：[executions.py](../../backend/src/model_platform/services/executions.py) 中 `finish` 对 `Job` 使用 `WHERE Job.status IN ("preparing", "running", "ready", "stopping")` 原子更新，杜绝已取消或终态任务被并发结案或产出新 `ModelVersion`；`store_artifact` 限制仅 `preparing`/`running` 态可上传产物。
- **并发乐观锁修复**：[annotations.py](../../backend/src/model_platform/services/annotations.py) `lock_batch` 与 [data_operations.py](../../backend/src/model_platform/services/data_operations.py) `publish_operation` 改用带 `WHERE revision == ...` 的条件更新并校验 `rowcount == 1`，避免并发改写丢失。
- **重跑接口幂等**：[jobs.py](../../backend/src/model_platform/api/jobs.py) `POST /jobs/{job_id}/retry` 支持可选 `Idempotency-Key` 请求头，重复请求返回同一重跑草稿。

### 2. 多端会话管理与管理端作业行内操作
- **多端会话管理**：
  - [auth.py](../../backend/src/model_platform/api/auth.py) 新增 `GET /api/v1/auth/sessions`、`DELETE /api/v1/auth/sessions/{session_id}` 与 `POST /api/v1/auth/sessions/revoke-others`。
  - [app.js](../../frontend/live/app.js)、[overview.js](../../frontend/live/pages/overview.js) 与 [events.js](../../frontend/live/events.js) 在用户空间（`/space`）展示活跃登录会话列表，支持单个退出与“踢出其他设备”。
- **管理端作业行内操作**：[administration.js](../../frontend/live/administration.js) 与 [events.js](../../frontend/live/events.js) 在 `/admin/jobs` 列表增加“操作”列，提供行内“取消/停止”与“重跑”按钮。
