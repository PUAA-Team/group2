## 2 核心业务对象

### MB01 中的二十个核心类

字段只列关键业务信息。编号及关系用于追踪；名称可修改，引用按标识匹配。业务资产记录所属工作空间与创建者，公共模型、节点和平台连接另按可见范围授权。

| 编号 | 中文名与类名 | 核心职责 | 关键属性 | 建议业务操作 |
| --- | --- | --- | --- | --- |
| O01 | 用户 User | 代表操作主体及账号状态 | userId、account、status、primaryGroupId | disable、enable |
| O02 | 角色 Role | 表达职责和允许操作 | roleId、name、allowedActions | allowsAction |
| O03 | 用户组 UserGroup | 提供基础授权及组上限 | groupId、name、grantRefs、quotaPolicyRef | changePolicy |
| O04 | 工作空间 Workspace | 组织成员与业务资产 | workspaceId、name、memberRefs、status | addMember、removeMember |
| O05 | 训练项目 TrainingProject | 组织多次训练和结果比较 | projectId、workspaceId、name、ownerId | addTask、listComparableTasks |
| O06 | 模型模板 ModelTemplate | 定义网络、任务、参数契约与执行能力 | templateId、taskType、supportedModes、parameterContract、runtimeRequirements | validateConfig |
| O07 | 模型版本 ModelVersion | 提供确定权重或适配器及来源 | versionId、entryId、templateId、artifactRefs、baseVersionId、sourceExecutionId | validateDependencies |
| O08 | 数据集 Dataset | 组织同一数据资产的版本 | datasetId、name、taskType、visibility | addVersion、checkDeletion |
| O09 | 数据版本 DatasetVersion | 固定样本、标签、划分与来源 | versionId、datasetId、parentVersionId、schema、manifest、splitRef、checksum、status | validate、publish |
| O10 | 训练任务 TrainingTask | 表示一次固定配置实验及其业务结果 | taskId、projectId、ownerId、taskType、status、submittedAt、priority、sourceTaskId | submit、requestStop、recordOutcome |
| O11 | 配置快照 ConfigSnapshot | 固定一次受理的完整输入 | snapshotId、templateId、initialModelVersionId 或随机初始化标记、datasetVersionId、splitRef、runtimeRef、parameters、resourceRequest、hash | freeze、checkCompatibility |
| O12 | 执行记录 ExecutionRecord | 跟踪实际派发、启动、事件与结束 | executionId、taskId、attemptNo、nodeId 或 providerExecutionId、phase、startedAt、finishedAt | confirmStart、recordEvent、recordExit |
| O13 | 计算节点 ComputeNode | 表达可接单 CPU/GPU 节点及运行能力 | nodeId、source、runtimeCapabilities、lastHeartbeatAt、health | register、recordHeartbeat、isolate |
| O14 | GPU 资源 GPUResource | 表达具体设备的能力和占用 | deviceId、nodeId、localIndex、memoryMiB、capabilities、allocationState | checkCapacity、changeAllocationState |
| O15 | 资源分配记录 ResourceAllocation | 跟踪预留、占用、释放与清理 | allocationId、ownerKind、ownerId、nodeId、deviceId、quantity、state、reservedAt、releasedAt | reserve、confirmUse、confirmRelease |
| O16 | 模型产物 ModelArtifact | 保存模型文件、检查点及校验结果 | artifactId、sourceExecutionId、kind、locationRef、size、checksum、integrityState | verifyIntegrity、archive |
| O17 | 推理服务 InferenceService | 发布指定模型、就绪检查、调用与停止 | serviceId、modelVersionId、runtimeRef、allocationRefs、accessPolicy、status | publish、confirmReady、requestStop |
| O18 | 审计记录 AuditRecord | 追溯关键操作与结果 | auditId、actorId、action、objectRef、occurredAt、result、reason | append |
| O19 | 外部模型连接 ExternalModelConnection | 管理辅助 API 渠道与能力 | connectionId、provider、endpointRef、modelName、capabilities、credentialRef、limits、status | testConnection、disable |
| O20 | 智能辅助请求 AssistantRequest | 跟踪一次解释、推荐或预标注 | requestId、kind、actorId、inputVersionRefs、authorizationRef、connectionId、status、resultRefs、usage | submit、cancel、recordResult |

以上类的方法表达对象负责的业务动作，任务编排由第 6 节控制职责完成。图中每个核心类先保留二至四个关键属性和一至两个关键操作，完整定义留在本表。C 若调整核心类范围，先说明原因并通知 D、E、F；不额外分画多张局部类图。

| 使用记录 UsageRecord | 主体、资源、来源分配、开始结束时间、使用量及单位；提供计量依据 |
| 运行环境模板 RuntimeTemplate | 编号、版本、框架、依赖、设备要求；校验环境兼容 |

| 日志条目 LogEntry | executionId、来源、序号、时间、级别、内容；支持检索与续传 |
| 评估任务 EvaluationTask | 模型版本、测试数据版本、指标契约、配置、状态；固定条件运行评估 |
| 评估报告 EvaluationReport | 评估任务、指标、样本结果和错误明细；支持比较与下载 |

## 3 关系和多重性

下表每一行同时说明两端，不把“有编号字段”直接当作关系已经画清。

| 关系 | 多重性与业务含义 | UML 表达 |
| --- | --- | --- |
| User 与 Role | 一个用户可具有多个角色，一个角色可对应多个用户 | 普通关联；继承仅用于确实存在的类型层次 |
| User 与 UserGroup | 当前工作约定为一个用户至多一个主组，一个组零至多个用户；未分组不获得组授权 | 普通关联；多组规则待定 |
| User 与 Workspace | 双方均可关联零至多个；成员关系附访问权限 | 普通关联 |
| Workspace 与 TrainingProject | 一个项目属于一个空间，空间有零至多个项目 | 普通关联，资产删除按保留策略 |
| TrainingProject 与 TrainingTask | 一个任务属于一个项目，项目有零至多个任务 | 普通关联 |
| TrainingTask 与 ConfigSnapshot | 草稿零或一份；已受理任务恰有一份独占固定快照 | 组合，菱形放任务端 |
| TrainingTask 与 ExecutionRecord | 任务有零至多条派发尝试，每条执行属于一个任务 | 组合并整体归档；重跑另建任务 |
| Dataset 与 DatasetVersion | 每个版本属于一个数据集，数据集有零至多个版本 | 普通关联；来源版本为可选自关联 |
| ModelTemplate 与 ModelVersion | 模型版本按一个模板解释执行，模板可对应多个版本；模型条目另组织版本 | 普通关联；基础模型依赖为可选自关联 |
| ConfigSnapshot 与输入 | 引用一个模板、一个可用数据版本和确定环境；初始权重版本零或一个 | 普通关联；随机初始化时初始权重为空 |
| ComputeNode 与 GPUResource | 每个设备属于一个节点；节点可无 GPU，也可有多个 | 普通关联；CPU 能力保留在节点 |
| ResourcePool 与 ComputeNode | 资源池组织节点；当前按节点至多归一个调度池，后续多池规则待确认 | 共享聚合可用于说明组织关系，移出池不删除节点 |
| ResourceAllocation 与所有者 | 一条分配属于一次执行或一个推理服务，二者恰选其一；各所有者可有多条分配 | 带约束的关联；CPU 分配可无 GPU 设备引用 |
| ExecutionRecord 与 ModelArtifact | 执行可产生多项产物；导入产物可无本平台来源执行 | 普通关联，独立保留产物 |
| ModelVersion 与 ModelArtifact | 一个可用版本引用一至多项完整产物；复用基础权重时保留依赖 | 普通关联 |
| InferenceService 与 ModelVersion | 每个服务固定一个模型版本，模型可被多个服务引用 | 普通关联 |
| AssistantRequest 与 ExternalModelConnection | 一次请求使用一个连接，连接被零至多个请求引用 | 普通关联 |
| AssistantRequest 与结果 | 一个请求零至多个候选结果；审核记录关联结果和新配置或新数据版本 | 请求与其结果可组合；新配置/数据版本独立存在 |
| AuditRecord 与主体对象 | 每条记录有操作主体和目标引用，可指向多种业务对象 | 带类型的对象引用，保留历史名称快照 |

聚合、组合和普通关联按生命周期选择，不为增加符号种类改变语义。图上的多重性必须与本表一致。计算节点、角色、模型等独立对象不随某次训练任务删除。

## 4 共同业务规则

| 编号 | 规则 |
| --- | --- |
| UR01 | 平台保留文本、视觉及现有表格任务范围。具体模板、模型和环境按真实接入能力开放；目录选项、页面演示和已验证执行分别标注。 |
| UR02 | 系统管理员、普通用户、只读访客为职责角色。工作空间限制业务可见范围；组提供基础授权、个人可追加允许或显式禁用。先合并组与个人允许，再排除任一来源的显式禁用，最后检查空间及对象访问约束。 |
| UR03 | 个人有效配额取组上限与个人上限的较小值，未设置个人上限时继承组上限；启动时扣除已用及预留。GPU 范围与允许任务类型都要检查，资源池分组不代替具体设备授权。 |
| UR04 | 项目组织多次训练；任务固定一次实验配置；执行记录追踪派发尝试。用户改参或重跑创建新任务并关联原任务，运行中的实验不被修改。 |
| UR05 | 清洗、标注发布、划分和增强生成可追溯新数据版本。可用版本及受理快照保持不变；草稿和候选可编辑，经校验审核后发布。删除先检查引用并执行保留策略。 |
| UR06 | 训练受理前检查身份、对象权限、参数、数据/模型/环境兼容及硬性上限；成功受理保存任务号、平台提交时间、快照和可恢复的排队记录，先返回标识，再异步执行。 |
| UR07 | 仅调度未接受取消、未被有效预留/领取的排队任务；同资源组按优先级降序、平台受理成功时间升序、稳定任务号排序。临时缺资源继续排队，永久越权或不兼容给明确原因。 |
| UR08 | 启动前再检查权限、设备、显存、环境和配额；原子预留后派发。实际训练启动确认才进入运行中，下载或准备环境记执行阶段。 |
| UR09 | 同用户、同空间、同提交标识及相同配置返回原任务；相同标识不同配置返回冲突。派发、事件、采纳和资源释放也要去重，结果未知先核查。 |
| UR10 | 日志、指标、故障都关联 executionId，事件有序号、源时间和接收时间。过期执行的事件保留证据，不覆盖当前执行；缺失与零值分别表示。 |
| UR11 | 排队取消为已取消，实际启动后停止为已停止。已接受停止先进入停止中；确认进程结束和清理完成才为已停止，超时保留停止中、告警和隔离。 |
| UR12 | 训练进程退出与业务成功分开判定，必要产物校验归档后才能成功。失败任务可以先登记失败，但未确认释放的资源继续占用或隔离。 |
| UR13 | Worker 主动接入、心跳、领取任务和上报事件。节点失联停止新派发，核对原执行后再恢复；个人 CPU、GPU 和云资源按能力匹配，不把多机显存直接相加。 |
| UR14 | 智能建议先展示候选、证据和差异，经人工确认、重新校验权限及版本后，创建新配置或新数据版本；重复确认返回原结果。 |
| UR15 | 外发日志、配置和样本范围待确认，授权落实前不发送真实内容。输入指令作为数据，输出经校验；模型不执行任意命令、提权、删除或开通付费资源。辅助失败保留人工路径。 |
| UR16 | 推理服务固定模型版本与依赖，独立检查权限、环境和配额，就绪后才接收请求；停止先拒绝新请求，再结束执行和清理。 |
| UR17 | 评估固定模型、测试版本、指标定义及配置；不同测试集或指标口径不直接比较为同条件优劣。LoRA 保留基础模型依赖，SFT 与 LoRA 分别表示目标和更新方式。 |
| UR18 | 时间展示注明北京时间，原始事件保存时区；容量注明 MiB/GiB，耗时注明秒/分钟，Accuracy/F1/mAP 的小数与百分数不混用。关联使用稳定标识，不依赖显示名称或本机 GPU 序号。 |

U-Net 按语义分割、Mask R-CNN 按实例分割归类。清洗当前采用明确的格式校验和精确去重规则；语义去重、生成增强、自动超参搜索等按后续范围单独分析。生成样本保留来源，测试集与验证集不得擅自用于生成训练数据。

## 5 统一状态

### 训练任务

| 当前状态 | 可转入状态 | 判断条件 |
| --- | --- | --- |
| 草稿 | 提交中、已取消 | 提交或放弃草稿 |
| 提交中 | 草稿、排队中、失败、已取消 | 未受理校验失败回草稿；受理后按排队或实际失败/取消记录 |
| 排队中 | 运行中、失败、已取消 | 实际启动确认、永久失败或取消；准备阶段仍记排队中并附阶段 |
| 运行中 | 停止中、成功、失败 | 停止已接受，或执行及必要产物处理确认结果 |
| 停止中 | 已停止、失败 | 结束与清理确认后已停止；独立执行错误记失败；超时暂不转终态 |
| 成功、失败、已取消、已停止 | 无 | 保留终态；重跑产生新任务 |

“运行中→已取消”不使用。取消与派发竞争时按服务端确认的启动事实处理：尚未真实启动则撤销指令并确认取消；已启动则转停止流程。准备过程中用户取消，也须确认准备进程结束及资源处理；清理未确认前不把设备显示为空闲。

停止与正常完成竞争时按服务端已确认结果裁决，记录请求与结果。训练终态和资源清理状态分别保存，不用“失败”直接推导“已释放”。准备、下载、训练、产物上传为 ExecutionRecord.phase，不增加另一套主状态。

### 其他对象

| 对象 | 统一状态或约束 |
| --- | --- |
| 数据版本 | 处理中、待处理、可用、失败；只有可用版本可供训练 |
| 推理服务 | 创建中、运行中、停止中、已停止、失败；创建中含加载与就绪检查 |
| 节点 | 待审核、在线、离线、维护、隔离 |
| GPU 占用 | 空闲、预留、使用中、不可用；健康状态另记 |

Worker 场景采用主动领取和控制轮询：调度器返回领取响应，Worker 经 nextControl 读取停止意图；训练状态回报经监控采集保存后交任务服务。外部托管平台按已调研的真实接口适配，提交结果未知时先查询核对，不假定所有平台支持同一种推送或取消协议。

同步调用用同步消息，异步通知/推送用异步消息，返回值用返回消息。alt 表达互斥条件，opt 表达可选动作，loop 表达重复，ref 引用本轮已有流程。调用返回“已受理”后，后续异步执行另画，不让前端一直等待整个训练结束。

### IX01 训练任务提交与异步执行总流程

负责人 D。来源 UC-TRN-03、UC-TRN-05，关联 UC-TRN-01、UC-TRN-02。前置为用户登录、有空间及项目权限，模型与数据可用，已完成配置。

1. 用户确认，前端发送 submitTask，携带提交标识、项目及完整配置。
2. 任务服务调用 authorizeAction，数据服务 requireUsableVersion，模型目录与仓库 validateConfig；任一未通过时返回具体错误，未受理请求不派发、不占资源。
3. 同标识同配置返回原受理结果；同标识不同配置返回冲突，不新建执行。
4. 校验通过后，任务服务保存 TrainingTask、ConfigSnapshot、平台受理时间及排队记录，返回 taskId、排队中、submittedAt、snapshotId。
5. 前端拿到结果后查询或订阅；任务服务异步 notifyQueued。调度唤醒失败可从已保存排队记录恢复，不丢失任务。
6. ref IX02：调度器重新检查约束，预留资源并生成执行指令，Worker 主动 claimAssignment 取得指令；准备阶段保持排队中并更新阶段。
7. Worker 真正启动训练后发送启动事实，经监控采集 ingestEvent 保存，再由任务服务处理为运行中；confirmStarted 作为该启动事实的业务操作，避免另建第二条不一致状态通道。
8. Worker 持续上报真实指标、日志和资源采样，ref IX10；任务服务及推送服务使前端看到实际变化。
9. 执行正常结束引用 IX11；必要产物完整后确认成功并通知用户。
10. alt 执行失败引用 IX05；取消引用 IX03；运行停止引用 IX04；节点失联引用 IX06。每条分支都说明任务结果与资源去向。

总图完整呈现“前端→任务服务→调度器→执行器/托管计算→监控采集→前端推送”。本地 Worker 作为主场景，外部托管执行以明确的适配分支或 ref 表达。权限、配置错误、资源不足与重复提交在图中可见。

| F10 | 停止超时、结束不明或清理失败 | 维持停止中或待清理，告警并隔离；授权处置须有真实结束/释放证据 | IX03、04、17 |
| F11 | 控制面重启、重复派发、外部提交结果未知 | 按持久执行标识查询并核对；事件和指令去重，结果未知不盲目再提交 | IX01、02、06 |
| F12 | 辅助 API 鉴权、超时、限流、额度或输出错误 | 请求失败或有限重试，保留人工操作；不自动切到未授权提供商，已运行训练不受影响 | IX09、12、13、14 |

恢复连接、重传产物和重新训练分别处理：前两者保留原任务；用户重跑创建新任务。检查点续训还需模板支持，以及权重、优化器/调度器、步数和其他必需训练状态完整兼容。只有权重文件时明确可做的加载方式，不保证完整续训。

## 10 源码图片和文字如何交付

每张图交可编辑工程或完整文本源码、同版 PNG 与 PDF/SVG、完整中文说明、用例/规则追踪和检查记录。文本源码为 UTF-8，公共定义连同版本提交，不交省略关键节点的片段。课程要求 CodeArts Modeling 时保留真实工程及同版导出，TikZ/PlantUML 等补充源码按实际工具注明。

类图核对属性、业务操作、关系两端、多重性及生命周期；顺序图核对生命线、消息、返回、分支条件、重复和引用。正式符号按 [OMG UML 2.5.1](https://www.omg.org/spec/UML/2.5.1/) 核对。页面截图只证明页面，不能替代可编辑模型。
