# Stage 16A 本地运行与验收

2026-11-11。旧服务器已停用。本阶段使用本机 D 盘环境、隔离 SQLite 和既有前端组件；数据库仍为 `0011_console`，Worker 协议保持原版本。

## 打开本地控制台

在项目根目录执行：

```powershell
.\backend\scripts\run_backend.ps1 -BackendAction migrate
.\backend\scripts\run_backend.ps1 -BackendAction serve
```

访问 [真实控制台](http://127.0.0.1:8000/)；首次空库登录前可用 `-EnableBrowserSetup` 开放回环初始化。启动命令默认不开启快捷 Worker。旧原型的 8765 服务独立运行。升级已有本地库时先正常停止平台进程并保留备份。

以管理员登录，进入「资源管理 → 计算节点 → 设备清单 → 配置策略」。将一个设备设为「训练与评估」，另一个设为「推理专用」；没有可用的多个节点时，可以分次体验。回到训练向导、创建评估及部署服务，比较选定 CPU/GPU 后的节点列表。任务自动选择时可以在资源不足的情况下排队；设备已有预留时调整用途会收到冲突提示。现有未设用途的设备会显示「共享」。

## 本地验收

- 后端：166 项通过、1 项跳过（Linux 子进程检查）。新增接口测试通过两个 CPU 节点的 Worker HTTP 协议请求验证训练、评估、在线服务分配、停止及释放；覆盖反向指定、策略修改与领取竞争、失联预留、设备授权、并发额度和旧请求兼容。训练产物使用测试夹具，未执行实际模型训练。
- 前端：129 项通过，覆盖配置表单、训练与评估节点过滤、部署和切换 CPU/GPU。通过 Node 测试验证表单逻辑，未执行浏览器截图验收。
- [OpenAPI](./openapi.json)由当前应用导出，共 131 个路径。设备策略请求和资源列表契约见[16A 设计](./16A设备用途与验收设计.md)。

复现方式：后端可执行 `.\backend\scripts\run_backend.ps1 -BackendAction test`；前端进入 `frontend` 后执行 `node --test --test-isolation=none`，使用已安装的 Node。测试不会连接旧服务器、启动本机 GPU 或调用外部大模型。

部署前需要在 PostgreSQL 重跑并发测试，并用真实 Worker 检查 CPU/GPU 和多机隔离。旧版本回退前先暂停新领取及设备策略写入，避免按共享规则分配专用设备。组、个人和全局额度仍共享；推理容量预留需要独立设计。
