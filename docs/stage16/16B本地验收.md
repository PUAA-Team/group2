# 16B 本地验收

2026-11-12 · 使用本机 D 盘既有 Python 环境和隔离 SQLite。数据库仍为 `0011_console`；没有新增依赖、启动旧 Worker、运行 GPU 或访问旧服务器。

| 场景 | 本地结果 |
| --- | --- |
| 210 条 GPU 任务挡在 CPU 任务前 | 旧调度器返回空；修复后 CPU 领取后排兼容任务，并保持优先级、创建时间、任务 ID 的次序。 |
| 201 条任务因个人额度为零无法派发 | 领取跨过多个批次，返回后排可运行任务。 |
| 两 Worker 同时领取；原 Worker 失联后重领 | 同一任务只产生一个执行；原 Worker 收回原执行 ID，另一节点拿不到该任务。 |
| 节点和设备汇总 | 汇总跨页且不受搜索影响；普通成员只看到所属空间，管理员可以查看全局。设备未上报但仍有占用时继续计入。 |
| 排队诊断 | 区分设备规格不满足、运行环境不兼容、离线或暂停、设备或槽位被占用。已有用途与额度提示继续可用。 |
| 排队优先级调整与资源细筛 | 2026-11-24（macOS 本地隔离环境）补齐：授权角色可调整排队中任务优先级（带 `revision` 校验与审计），生效后按新优先级领取；`admin/nodes` 与工作空间 `resources` 支持 `device_kind` 与 `purpose` 组合筛选且保持 `summary` 独立统计。 |

后端全量 173 项通过、1 项跳过（Linux 子进程检查）；前端 132 项通过。使用测试节点的 HTTP 请求验证领取和回执，没有运行真实训练。前端通过 Node 测试，未做浏览器截图验收。[OpenAPI](./openapi.json)与本批实现对应。

本地启动和测试命令沿用 [16A 本地运行](./运行与验收.md)。启动后在「资源监控」或「资源管理」的列表上方查看在线节点、CPU/GPU 占用、失联占用；任务在排队时可在详情中查看等待原因。

本批不需要迁移或转换数据。需要回退时，停止当前控制端后可恢复 16A 程序；已有设备用途和预留记录保留，资源汇总会消失，队首截断的旧限制也会恢复。部署前还需验证 PostgreSQL 的并发和锁等待、多台物理机，以及超长匹配队列下的耗时。
