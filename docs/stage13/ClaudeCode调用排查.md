# Claude Code CLI 调用排查

2026-10-31，独立排查 agent 已完成回复、读取和写入三类验证。没有修改全局配置、环境变量或模型映射。

## 结论

CLI 经本机 Magpie 网关调用配置的模型服务。当前 Haiku、Sonnet、Opus 别名被映射到其他模型，因此不能根据别名判断实际供应商或计费。

原 `agents:` 路由出现 `Server error mid-response`，CLI退出码为1。接口侧记录成功，说明上游处理过请求；CLI还需接收完整的流式响应、解析工具调用并完成后续轮次。这些环节中断时，接口侧成功与CLI失败可以同时发生。目前证据指向这条路由的流式链路，尚不能定位到网关或上游的某个具体实现。

显式路由 `api2/cn:deepseek-v4.1-flash` 配合 `--effort low` 已成功。`unrecognized_model` 警告在成功调用中也会出现，判断完成应以退出码、完整结果和实际文件为准。

| 验证 | 实际结果 |
| --- | --- |
| 普通回复 | 约27秒，退出码0 |
| 单文件读取 | 约11秒、2轮，退出码0 |

写入验证只创建了[探测文件](./claude-cli-probe.txt)，内容为“CLI写入验证”，已由主负责者读取确认。此前较大的探索和双文件实现分别耗尽7轮、18轮，没有产生交付；这类情况需要缩小任务范围，不能视为写工具不可用。

## 后续使用

优先指定已验证的完整模型路由，每次只委派一个文件、函数或明确问题。说明允许使用的工具、预期结果和停止条件；读取或编辑完成后核对实际文件，再提交下一项任务。读取任务使用只读工具与plan权限；确需写入时仅开放对应工具及授权范围。不使用绕过权限检查的选项。

用户已允许非敏感源码和设计文档发送到现有CLI服务。密钥、私有配置、数据库、日志和真实业务数据继续排除。本机资源暂停期间，CLI仅做轻量阅读与编辑；测试、构建、浏览器、Worker及训练在云端执行。CLI返回的费用估计不代表网关实际账单。
