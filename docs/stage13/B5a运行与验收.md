## 使用

在“模型评估”中选择2～6个已完成评估，点击对比。系统要求同一任务类型、不可变数据版本和评估配置，展示实际指标、模型版本及混淆矩阵。缺失指标显示为空，0保留为0。分类评估可以查看错误样本；旧Worker未报告样本级结果时，页面明确显示未报告，不能从混淆矩阵反推样本。

在线服务详情新增调用记录、状态筛选和实际计时。耗时从服务端接受请求到回传完成计算，包含等待时间。旧记录没有计时值，统计时不补造。汇总接口只返回状态、时间和调用人，不返回输入、输出正文。

API KEY管理可以在确认弹窗后轮换。仅创建人且具有当前空间服务维护权限时可执行；事务内撤销旧值并创建新值，原到期时间保留，新值只展示一次。关闭展示后不能再次读取，原密钥立即失效。

当前契约见[OpenAPI](./openapi-b5a.json)。错误样本接口为`GET /api/v1/workspaces/{workspace_id}/jobs/{job_id}/error-samples`，需要训练读取和数据读取权限。评估完成结果上限64KiB，错误样本最多100条；服务端核对索引、源标签、任务空间与执行快照摘要。

## 验证

最终发布镜像内121项后端测试、云端109项前端测试通过。浏览器检查8个页面、1440/1024/390三种宽度，共24项布局，以及选择双评估、轮换确认和调用筛选三项交互；受检字号至少14px，无整页横向溢出或JavaScript异常。仍有既有Starlette/HTTPX测试适配弃用提示，未为此新增依赖。

两个独立CPU容器Worker分别完成真实文本分类训练、权重回传和模型登记，再用相同8条合成样本评估两版模型，核对错误索引、原文及标签。验证集刻意包含成对矛盾标签，用于稳定验证错误定位；准确率50%不能解释为模型能力结论。随后实际部署CPU服务，完成普通调用与新密钥调用，验证旧密钥拒绝和两条真实耗时记录。所有训练只在云端执行，两个容器共用一台ECS。

真实验收发现Linux僵尸子进程仍能通过`kill(pid,0)`检查，导致结果等待不结束。先通过失败测试复现，再增加子进程回收和退出状态检查；保留启动不明状态的人工核查机制。另补齐隔离镜像的NumPy2.2.6，并使训练器探测检查这一权重序列化依赖。测试镜像未加入生产Compose，本机环境未改。

部署后通过公网真实登录，检查新调用查询接口及schema7，原节点暂停状态不变。[截图与机器记录](./previews/b5a/ReadMe.md)。
