# B5 资源、结果与服务

沿用B4模块化单体、独立Worker和现有云管控界面。先交付评估对比、服务调用记录和密钥轮换，再交付资源治理及资产生命周期。每批独立验收与发布，保留旧数据和用户暂停设置。所有测试、构建与浏览器检查在云端进行。

## 结果与服务

评估列表选择2～6个已完成评估，进入独立对比页。服务端限定同一空间、任务类型和不可变数据版本，同时要求相同评估配置；Qwen比较响应Token loss/困惑度，分类比较accuracy、Macro F1、Loss、混淆矩阵。未报告的指标显示缺失，不能补零或生成排名。参数、模型版本和数据版本与原记录一起展示。

服务详情新增调用记录与统计，包含状态、创建/完成时间、耗时和调用人。默认列表不返回输入正文或图像；单条详情仍由原调用人读取。管理者只读取汇总与脱敏错误。密钥轮换在一个事务内撤销旧密钥并创建新密钥，新值只展示一次。保留原到期时间，轮换不延长授权。新增调用完成时间字段，旧记录耗时未知。

增量接口均位于`/api/v1/workspaces/{workspace_id}`：

| 方法与路径 | 约束 |
| --- | --- |
| GET `/evaluation-comparison?ids=...` | training.read；2～6个不同评估ID；同数据、同任务和同评估配置 |
| GET `/jobs/{id}/call-history` | services.read；分页、状态筛选；不返回输入/输出正文 |
| GET `/jobs/{id}/call-statistics` | services.read；实际计数与已知耗时分布 |
| POST `/service-keys/{id}/rotate` | services.write且原创建人；事务内撤销旧值，返回一次新值 |

错误样本来自Worker真实评估结果。分类评估最多报告100条样本序号、真实标签和预测标签；服务端复核源版本索引及标签。没有该能力的旧结果保留缺失状态，不根据混淆矩阵反推样本。

任务与推理结果的JSON均限64KiB，事件仍限8KiB。分类错误样本在100条和字节限制之间取可容纳的子集，保留实际错误总数及截断标记。超限推理结果返回失败调用，服务继续运行，避免反复提交同一不可接收结果。

## 资源治理

真实心跳每30秒最多保存一条节点采样，保存7天，查询返回受限时间窗口和稀疏曲线。没有历史采样的时段保持空白。节点当前状态继续由心跳、审批和暂停设置判断。

设备授权绑定设备记录，可分别配置允许用户/组与禁止用户/组、启停。默认沿用所属空间的现有可用范围，显式禁止优先。授权在调度领取前复核；不能让已经暂停的节点自动恢复。管理员在节点详情的弹窗设置授权。

组共享预算使用独立配置，GPU、并发、文件存储可分别留空表示未另设上限。现有组quota继续作为个人继承上限。执行时固定计入的组ID，成员换组不转移已有占用。调度在现有全局锁及个人锁后检查组预算，再原子预留设备。

存储按服务端实际对象文件字节计量：数据版本、训练产物及数据处理候选。新对象固定所有者和计入组，写入前检查个人与组剩余额度；历史归属优先从已有创建审计恢复，无法确认的记录列为未归属，不编造历史组。数据库本身、基础模型远端引用和Worker本机缓存单独说明，不计为服务端对象文件。归档继续占存储，不等于删除或释放额度。

增量接口：节点历史`GET /resources/nodes/{id}/history`；设备授权`GET/POST /resources/devices/{id}/policy`；组预算`GET/POST /admin/groups/{id}/budget`；当前用户/空间存储汇总`GET /workspaces/{id}/storage-usage`。修改接口校验revision并写审计。

现有管理员统计接口补充文件字节、已结束GPU预留时长、已确认智能请求、供应商实际报告的Token与失败阶段。预留时长按执行领取到结束的时间计算，不推测GPU计算忙碌时间；未知阶段单独统计。管理员资产目录返回创建审计可追溯的人名、归档状态及该资产实际文件账目字节，缺少创建记录时保留未知。目录`status=active/archived`用于归档筛选。

作业管理除训练、评估和服务外，补充数据处理与智能请求两个标签。`GET /admin/workflow-catalog/{kind}`（operations/assistants）分别需要管理员datasets.read/assistants.use，支持space/status/q/page/page_size。列表只返回名称、空间、创建人、类型、状态、时间、已报告Token和错误码；不返回样本、外发消息、预览、模型结果、候选文件或密钥，详情沿用原业务权限接口。

审计补记已认证账号的失败写操作，记录动作、目标、错误码和服务端请求编号，不保存请求正文、错误详情或查询参数。认证完成前的失败不冒记为某个用户的操作。失败事务先回滚，再独立写审计；审计写入失败不替换原业务响应。现有审计查询增加nullable的error_code/request_id，管理员按success/failure筛选。

Worker运行时新增execution_contract_version，旧客户端缺省0，新版本报告1。新任务只派给版本至少1的Worker，确保其能处理永久输入/存储拒绝与进程退出；已领取任务保留原回执路径。节点详情展示升级状态与Worker下载入口。升级前暂停节点、确认没有运行进程，再替换原worker.pyz并用原状态目录启动，不重新注册身份。

schema8新增资源治理，schema9独立增加失败审计字段。应急兼容版本只开放GET/HEAD/OPTIONS及登录、退出；回退前停用operations并确认没有执行中任务。新增账目与记录保留，避免旧写入路径绕开设备、预算和归档规则。

失联执行提供核查详情和人工结案弹窗。先暂停节点，展示最后心跳、最后上报执行、资源占用与日志；管理员确认已经在目标机器检查进程退出后，带原因和revision结案。在线且仍上报执行的节点拒绝人工释放。结案状态为失败或停止，保留人工核查记录，旧Worker的迟到回执不能覆盖。

## 资产与验收

模型和数据集可归档、恢复。归档后禁止新增版本、生成新候选及新提交任务，历史快照、下载和审计保留；不提供直接删除文件。队列任务领取前也检查资产归档状态，已运行任务继续依赖既有快照。

每个功能覆盖跨空间/跨成员拒绝、重复请求、权限撤销及并发边界。资源、配额和存储的竞争用例另在隔离PostgreSQL上验证。分类错误样本通过云端隔离CPU任务产生；不启动用户本机Worker或GPU。最后以三种视口复核新表格、详情、对比及弹窗，再备份、迁移并发布。
