# Stage 19A：SSRF 钉扎、CSRF 密钥分离、Worker 鲁棒性与部署加固

## 完成范围

### 1. 后端安全加固
- **SSRF IP 钉扎与路径规范化**：[model_connections.py](../../backend/src/model_platform/services/model_connections.py) 中 `validate_remote()` 禁止 URL 中的 `query`/`fragment` 并规范化基础路径（过滤 `.`、`..`），完成单次 DNS 解析与全地址公网校验后返回 `pinned_url`、`host` 与 `sni_hostname`；`completion()` 直接连接钉扎 IP 并携带 `Host` 头与 TLS `sni_hostname` 扩展，防止 DNS 重绑定（TOCTOU）。
- **CSRF 独立服务端密钥**：[config.py](../../backend/src/model_platform/config.py) 新增 `csrf_secret` / `resolved_csrf_secret`（优先读取 `MT_CSRF_SECRET`，未配置时在 `runtime_dir/private/csrf.key` 以 `0600` 权限持久化）；[security.py](../../backend/src/model_platform/security.py)、[deps.py](../../backend/src/model_platform/api/deps.py)、[identity.py](../../backend/src/model_platform/services/identity.py) 与 [auth.py](../../backend/src/model_platform/api/auth.py) 均改为使用服务端独立密钥签发和校验 CSRF HMAC。

### 2. Worker 安全与鲁棒性
- **主循环与单任务异常隔离**：[executor.py](../../backend/src/model_platform/../../worker/src/training_worker/executor.py) 将 `tick()` 按任务拆分为 `_tick_one()` 并捕获单任务非通信异常写入 `result.json`（`failed`），防止单个任务异常拖垮整个 Worker 进程。
- **子进程句柄、超时看门狗与退出清理**：`Executor` 保存 `Popen` 句柄并优先以 `proc.poll()` 判定存活，避免僵尸进程误判；增加超时看门狗（`MT_WORKER_MAX_SECONDS`，默认 `14400` 秒）；[agent.py](../../worker/src/training_worker/agent.py) 在退出时调用 `executor.shutdown()` 清理遗留子进程。
- **推理长度边界**：[inference_contract.py](../../worker/src/training_worker/inference_contract.py) 限定 `max_new_tokens` 必须为 `1..2048` 区间内的整数。

### 3. 生产部署加固
- **容器入口白名单收敛**：[entrypoint.py](../../deploy/server/entrypoint.py) 限制 `cli` 模式仅允许 `{"migrate", "bootstrap-admin", "export-openapi"}` 子命令。
- **证书续期备份与代理清理**：[renew_certificate.py](../../deploy/server/renew_certificate.py) 移除不校验身份的 `127.0.0.1:18080` 回退通道，续期前自动备份 `certificates` 目录。
- **全量备份脚本**：新增 [backup.sh](../../deploy/server/backup.sh)，支持 `pg_dump -Fc` 与 `runtime/storage` 归档并保留最近 7 份备份。

## 验证结果
- 后端全量测试（`cd backend && ../.venv/bin/python -m pytest -q`）：`187 passed, 1 skipped`（含 [test_stage19a_security_worker.py](../../backend/tests/test_stage19a_security_worker.py) 3 项）。
- 前端全量测试（`cd frontend && node --test --test-isolation=none`）：`140 pass, 0 fail`。

# Stage 19B-1：Worker 凭据轮换与已撤销节点防复活

分支：`lx/stage19b-1-credential-rotation`（基线 `lx/stage19a-worker-deploy-hardening` 719565d，未合并 main，未部署）。

## 完成范围

### 1. 已撤销节点禁止原地复活
- [compute.py](../../backend/src/model_platform/services/compute.py) 的 `register_node()`：`machine_id` 命中已撤销旧节点时不再覆写旧记录，旧节点原样保留（历史审计与关联执行仍指向旧节点 ID），一律新建独立 `ComputeNode`（`new_id("nod")`）。旧节点仍有未结束执行或设备占用时拒绝重新接入。
- 方案选择：新建独立节点 + 部分唯一索引。只新建节点而不改约束会撞 `machine_id` / `installation_id` 全局唯一；只改约束不新建节点则旧记录仍会被覆写，两者缺一不可。
- [compute_models.py](../../backend/src/model_platform/compute_models.py)：`machine_id` / `installation_id` 取消全局唯一，仅对未撤销节点建部分唯一索引；`ComputeDevice.hardware_id` 由全局唯一改为 `(node_id, hardware_id)` 复合唯一，否则新节点按同一硬件标识重建设备行时会撞唯一约束。
- [0014 迁移](../../backend/migrations/versions/0014_worker_credential_rotation.py)（`0014_worker_credential`，schema 0014）：新增 `compute_nodes.credential_expires_at`；SQLite 下 0002 建表时唯一约束未命名、inspector 返回 `name=None` 且 batch 无法按名删除，改用显式建表 + 复制数据 + 改名重建表，迁移后做 `PRAGMA foreign_key_check`；PostgreSQL 按约束名删除后建部分唯一索引。升降级往返已在空库验证通过。

### 2. Worker 凭据轮换与过期
- 新增 `POST /api/worker/v1/rotate-credential`（[worker.py](../../backend/src/model_platform/api/worker.py)）：凭据为 Bearer 认证，换发新随机凭据（`secrets.token_urlsafe(48)`，只在本次响应返回一次，服务端只存摘要），旧凭据立即失效；过期时间 `credential_expires_at` 默认 90 天，可用 `MT_WORKER_CREDENTIAL_DAYS` 覆盖（[config.py](../../backend/src/model_platform/config.py)）。
- [worker_auth.py](../../backend/src/model_platform/api/worker_auth.py)：凭据过期与轮换后旧凭据一样返回 401；旧数据 `credential_expires_at` 为空时视为未过期，下次注册/轮换后填入。轮换不写审计事件：审计表要求用户 actor，Worker 侧没有用户身份（心跳同样不审计）。
- [agent.py](../../worker/src/training_worker/agent.py)：注册回执与心跳回执带回 `credential_expires_at` 并存入本地状态；凭据临期（7 天内）或已过期时，启动后与每次心跳后自动调用轮换，新凭据经 `write_json`（临时文件 + fsync + 原子替换）写入 `node-state.json`；轮换失败只打印日志、不中断 Worker，旧凭据过期前仍可用，下次心跳再试。

### 3. 附带修复
- [compute_views.py](../../backend/src/model_platform/services/compute_views.py)：`node_view` 的 `serialize()` 会带上新增的 `credential_expires_at` 列，`NodeOut` 为 `extra="forbid"` 会导致节点详情接口 500，已将其排除（首轮全量测试 18 项失败均为此原因）。

## 验证结果

- 前端全量测试（`cd frontend && node --test --test-isolation=none`）：`140 pass, 0 fail`（本阶段前端无改动）。
- 迁移升降级往返（SQLite 空库）：0013 → 0014 → 0013 → head 通过；同一 `machine_id` 的已撤销 + 未撤销节点及同硬件设备行可共存。
