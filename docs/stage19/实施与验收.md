# Stage 19A：SSRF 钉扎、CSRF 密钥分离、Worker 鲁棒性与部署加固

## 完成范围

### 1. 后端安全加固
- **SSRF IP 钉扎与路径规范化**：[model_connections.py](../../backend/src/model_platform/services/model_connections.py) 中 `validate_remote()` 禁止 URL 中的 `query`/`fragment` 并规范化基础路径（过滤 `.`、`..`），完成单次 DNS 解析与全地址公网校验后返回 `pinned_url`、`host` 与 `sni_hostname`；`completion()` 直接连接钉扎 IP 并携带 `Host` 头与 TLS `sni_hostname` 扩展，防止 DNS 重绑定（TOCTOU）。
- **CSRF 独立服务端密钥**：[config.py](../../backend/src/model_platform/config.py) 新增 `csrf_secret` / `resolved_csrf_secret`（优先读取 `MT_CSRF_SECRET`，未配置时在 `runtime_dir/private/csrf.key` 以 `0600` 权限持久化）；[security.py](../../backend/src/model_platform/security.py)、[deps.py](../../backend/src/model_platform/api/deps.py)、[identity.py](../../backend/src/model_platform/services/identity.py) 与 [auth.py](../../backend/src/model_platform/api/auth.py) 均改为使用服务端独立密钥签发和校验 CSRF HMAC。

### 2. Worker 安全与鲁棒性
- **主循环与单任务异常隔离**：[executor.py](../../backend/src/model_platform/../../worker/src/training_worker/executor.py) 将 `tick()` 按任务拆分为 `_tick_one()` 并捕获单任务非通信异常写入 `result.json`（`failed`），防止单个任务异常拖垮整个 Worker 进程。
- **子进程句柄、超时看门狗与退出清理**：`Executor` 保存 `Popen` 句柄并优先以 `proc.poll()` 判定存活，避免僵尸进程误判；增加超时看门狗（`MT_WORKER_MAX_SECONDS`，默认 `14400` 秒）；[agent.py](../../worker/src/training_worker/agent.py) 在退出时调用 `executor.shutdown()` 清理遗留子进程。
- **推理长度边界**：[inference_contract.py](../../worker/src/training_worker/inference_contract.py) 限定 `max_new_tokens` 必须为 `1..2048` 区间内的整数。

### 3. 生产部署加固
- **容器入口白名单收敛**：[entrypoint.py](../../deploy/server/entrypoint.py) 限制 `cli` 模式仅允许 `{"migrate", "bootstrap-admin", "export-openapi"}` 子命令。
- **证书续期备份与代理清理**：[renew_certificate.py](../../deploy/server/renew_certificate.py) 移除不校验身份的 `127.0.0.1:18080` 回退通道，续期前自动备份 `certificates` 目录。
- **全量备份脚本**：新增 [backup.sh](../../deploy/server/backup.sh)，支持 `pg_dump -Fc` 与 `runtime/storage` 归档并保留最近 7 份备份。
