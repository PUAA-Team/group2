一、任务概述
（一）任务背景
随着大语言模型与多模态模型技术的快速发展，如何高效实现大规模模型的训练
与部署，已成为学术界与产业界共同关注的核心议题。大模型集成训练平台面向企业
和开发者，提供模型训练、优化、在线服务部署等一站式服务，支持多种开源大模型
的接入与适配，通过简化操作流程与灵活资源配置，帮助用户高效完成大模型训练与
推理。
本项目定位建设一套面向企业和开发者设计的大模型集成训练平台。该平台由专
门的管理机构运行和维护，按照用户需求和技术标准进行配置管理。其基本的运行和
管理机制包括以下几个方面：
1. 多模型集成与支持：平台应集成多种神经网络的训练和推理功能，包括但不限
于大语言模型和视觉模型，如 LLaMA、Qwen、DeepSeek 等。用户通过 Web 界面配
置参数，选择所需的模型及训练环境，启动模型训练或推理任务。例如，用户在 web
页面，选择基础模型、选择数据集、选择显卡编号、设置 batch size，epoch等参数，
即可启动模型训练。
2. 资源调度与管理：普通用户可以在多卡环境中选择显卡资源，启动模型训练。
系统管理员负责配置普通用户可使用的显卡编号，并指定其可以启动的任务类型。例
如，管理员可以限制用户 A 仅使用显卡 2 和显卡 3，并只能启动大语言模型的微调任
务，而无法启动视觉模型的训练。
3. 任务监控与日志管理：平台需提供实时的任务监控和日志记录功能。用户可以
通过 Web 界面实时查看训练进度、loss 变化等关键指标。同时，平台应支持日志导出
和分析功能，以便用户在训练任务完成后进行详细的数据分析和调优。
4. 数据管理与存储：因为多源异构数据需要定制化规则较多，所以本平台可以支
持数据预处理功能。平台应支持数据集的集中管理和高效存储。用户也可以上传已经
改好格式的数据集，即无需处理，直接用于模型训练。
5. 扩展与升级：系统一期定位于多种模型的训练、推理等基本需求，后期成熟后，
可以考虑提供有偿增值服务，如付费使用高性能计算资源、专业的模型优化咨询服务
等，以进一步增强平台的商业价值。

（二）实践目标
1. 知识目标
掌握需求工程全过程与 UML 建模方法；掌握软件架构设计方法（分层架构、微服
务架构、架构决策记录）；掌握数据工程相关知识（多源数据采集、ETL 数据管道、
数据清洗与去重、增量更新机制）；掌握全文检索与数据分析设计（Elasticsearch、
检索排序、共现分析）；掌握数据库设计与 RESTful 接口设计；理解 DevOps 工程实
践。
2. 能力目标
能够对数据密集型业务系统完成需求分析与架构设计；能够设计与实现多源异构
数据采集、清洗、存储、检索与统计分析全链路；能够基于华为云 CodeArts 完成系统
实现、测试与部署；能够运用码道代码智能体、MCP、规范驱动开发（SDD）等
Agentic Coding 技术提升开发效率与质量，并对 AI 生成内容进行验证与权衡；能够撰
写规范的项目文档并进行有效的团队协作与工程汇报。
3. 素质目标
树立数据质量意识与数据治理观念，理解数据合规与爬虫伦理边界；培养学术诚
信意识（成果认领审核、防冒领）；培养批判性思维、创新意识与团队协作能力。
（三）总体要求
1. 以团队形式完成从数据采集到统计分析、再到部署演示的完整软件生命周期；
2. 采用“规范驱动开发（SDD）＋敏捷迭代”的开发流程，先写规范、再写代码；
3. 基于华为云CodeArts完成需求管理、代码托管、代码检查、构建、测试、流水
线部署的全流程；

三、Agentic Coding 实践要求
将当前 Agentic Coding 前沿技术纳入课程实践。以下内容须在最终答辩中展示完
整证据。
（一）规范驱动开发（SDD）
1. 编码前为每个核心模块编写开发规范（SPEC）：做什么（功能）、怎么做（接
口/算法/约束）、做到什么程度（验收标准）；
2. 规范先行、代码履约：要求 Agent 生成代码前必须先存在对应规范，规范纳入
版本管理，与源码同等对待；
3. 规范评审记录存档（评审意见＋修改记录）。
交付证据：SPEC文档目录、规范—代码对应关系表。
（二）项目上下文文件（AGENTS.md）
在仓库根目录建立 AGENTS.md，记录常用构建/测试命令、架构概览、数据流、
团队约定与关键约束，并保持精简；该文件是 Agent 的长期项目记忆，每次开发前由
Agent读取。
交付证据：AGENTS.md文件及内容说明。
（三）CodeArts 代码智能体深度应用
1. 使用代码智能体完成 5 类任务：项目级代码生成、代码续写、代码解释、单元
测试、调试自愈/代码修复；
2. 对 AI 生成代码进行人工审查与修改，记录“AI 生成→人工修正”关键案例至少 3
个；
3. 总结代码智能体的能力边界与失效模式。
交付证据：AI使用日志、修正案例记录。

（四）上下文工程与防御性提示
1. 控制 Agent 上下文，规避四种失败模式：上下文污染（早期错误被固化）、上
下文分心（超长上下文后开始复读自身历史）、上下文混乱（工具过多导致性能下
降）、上下文冲突（矛盾信息导致准确率骤降）；
2. 采用防御性提示编写规范：精确（说清“怎么做”而非泛泛而谈）、预判依赖、
设置人工检查点、使用强类型语言与类型标注；
3. 对预计超过1小时的 Agent长任务设置人工确认检查点。
交付证据：规范文档中的防御性设计说明。
（五）AI 辅助测试与代码审查
1. 使用AI生成单元测试用例，核心模块行覆盖率不低于 80%的模块不少于 3个；
2. 代码审查遵循“AI Gold Zone／Human Zone”分工：简单bug、性能、安全与
风格问题由AI审查负责，业务逻辑与关键决策由人工审查负责；
3. 记录AI审查与人工审查的对比结论（AI漏报与误报案例）。
交付证据：测试报告、审查记录。
（六）提示词资产管理
1. 所有用于开发的提示词与规范模板纳入版本管理（prompt 即源码），不得丢弃；
2. 建立提示词资产清单：用途、版本、效果评估。
交付证据：提示词资产清单。
