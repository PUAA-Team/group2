# 训练执行设计

## 执行与存储

控制端持有项目、任务、固定输入版本、执行记录及事件。Worker 通过独立凭据领取本空间任务，在独立子进程运行训练器。每个设备最多一个执行，节点同时受槽位限制。模型模板映射到随包发布的训练器，用户输入不能变成任意命令或 Python 代码。

每次提交固化模型版本、数据版本、参数、训练器版本和内容哈希。文本采用字符特征线性网络，图像采用小型 CNN，语言模型采用 Qwen3-0.6B LoRA；Qwen 基础权重固定公开仓库提交。支持从平台产物继续训练。新增模型须选择兼容训练器；首版不执行任意外部仓库代码。

数据和产物由主服务器保存。Worker 下载接口校验节点与执行归属，只能读取本次任务所引用文件；内容缓存按 SHA256 命名。分类权重保存为 safetensors，LoRA 保存适配器；压缩包只接受白名单 JSON 与 safetensors，不加载 pickle。Qwen 基础权重保存在 Worker 的模型缓存，后续再接对象存储统一分发。

## 状态和故障

草稿 → 排队 → 准备 → 运行 → 成功/失败。排队取消为已取消；执行后请求停止先进入停止中，子进程结束回执后为已停止。重跑创建新任务，旧任务快照与结果保留。

Worker 先持久化执行日志再启动子进程。相同执行 ID 不重复启动；事件使用递增序号，重复相同事件可重传，内容冲突拒绝。子进程将事件、结果与服务调用结果写入执行目录；Agent 重启后继续读取，不重新启动同一个执行。无法确认原进程已结束时保留占用，不能凭心跳超时释放设备。

派发在事务中核验授权、角色、设备、显存、运行时、个人并发和 GPU 额度，按优先级与创建时间选择任务。用户组额度与个人额度取较小值；管理员同样需要明确额度。显存按设备总量筛选，CUDA 实际可用量仍可能变化；显存不足作为真实失败返回。组共享总预算和存储扣额尚待后续实现。

分类数据按种子分层划分训练/验证；每类至少两条，特征词表只读取训练集。预置数据为程序生成的教学样本，指标仅验证流程。图像 ZIP 包含 labels.csv（filename,label）和 PNG/JPEG，拒绝路径穿越、重复路径、符号链接、异常压缩比、超限尺寸和不可解码图片。上传不会解压到任意目录。

## API

浏览器 `/api/v1/workspaces/{id}` 下提供 `/projects`、`/jobs`、`/jobs/{id}`、`/jobs/{id}/submit`、`/stop`、`/retry`、`/events`、`/artifact`、`/presets`。草稿修改和提交使用 If-Match；提交以状态及版本检查保持幂等。产物仅在校验和入库成功后显示可用。

Worker `/api/worker/v1` 下提供 `/claim`、`/executions/{id}/events`、`/control`、`/input`、`/model`、`/artifact`、`/finish`。事件和完成回执幂等；输入下载及回传均校验执行归属。租约只用于观察执行健康度，失联不重派。

监控页面轮询真实事件，曲线来自训练器计算；断线保留数据并显示错误。部署及评估复用同一执行协议，业务规则见 stage9。

参考实现：[PyTorch 训练教程](https://docs.pytorch.org/tutorials/beginner/introyt/trainingyt.html)、[PEFT 官方仓库](https://github.com/huggingface/peft)、[LoRA 配置](https://huggingface.co/docs/peft/package_reference/lora)。本项目按既有 Torch 2.5.1 和 PEFT 0.18.1 环境验证。
