## 服务器操作

本机已配置免密SSH：

```powershell
ssh training-demo
```

进入服务器后查看和重启现有版本：

```bash
cd /srv/model-platform/current/deploy/server
docker compose --env-file .env ps --all
docker compose --env-file .env logs --tail 100 api
docker compose --env-file .env up -d --no-build
```

`.env`权限为0600，内含两个独立随机数据库口令。检查配置使用 `docker compose --env-file .env config --quiet`，不要将完整环境配置输出到截图、聊天或公开日志。正式数据库不接受公网连接，安全组需保留TCP5488和证书验证所需TCP80；SSH按使用者的来源规则开放。

发布前先备份数据库及其引用文件。上传新包到新的版本目录，核对清单和SHA256，沿用受限配置与持久化目录，构建新镜像、验证迁移与测试后再切换current。已有版本20261029-01至03保留；代码回滚不自动回退数据。当前API仍见[stage11](../stage11/openapi.json)，本次未新增API或迁移版本。

## 备份和恢复

服务器备份位于 `/srv/model-platform/backups/post-first-gpu-20261029`：platform.dump为PostgreSQL自定义格式，storage.tar.gz为数据集及模型产物，compose.env为受限配置。已用pg_restore列出备份内容检查格式，尚未执行整套灾难恢复演练。按用户决定，不把数据库或存储备份下载本机。

恢复时先在新数据库和新文件目录进行，保留现有数据。使用相应应用版本，创建专用数据库角色，将platform.dump恢复到新库，再恢复storage、校验文件摘要和权限，修改受限连接配置后检查readyz、登录和训练产物。确认成功后切换，不能把旧备份直接覆盖正在运行的库。

当前备份和应用仍在同一台ECS，不能覆盖云盘整体丢失。抢占式实例的磁盘保留设置需在阿里云控制台核对。对象存储、缓存优先调度、传输预算、多个Worker并行和长时间稳定性后续单独实施；智能标注、参数推荐和日志解释仍待真实API接入。
