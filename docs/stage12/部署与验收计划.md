# 部署与验收计划

## 范围与数据

本次把当前 FastAPI 控制端和真实前端部署到北京 Linux 服务器，Windows 本机作为远程 GPU Worker。首个验收任务选用现有 TinyCNN 图像分类训练器和内置教学图像样本，以实际 CUDA 执行验证通信、文件传输、指标和产物入库；教学样本结果用于流程验收。

云端先采用独立数据库和预置数据。现有本机账号、历史训练、模型和推理服务不自动迁移。若需要迁移历史，先单独核对数据库、文件、节点身份和未结束执行，不能把带本机路径与旧 Worker 占用的数据库直接当作可运行云端数据。

控制端代码、前端和 Worker 源码保持仓库中的相对位置。候选目录为 `/srv/model-platform/releases/<release-id>`；可写数据、日志、临时文件和环境配置放在独立 `runtime` 目录。代码切换与数据目录分开，发布前备份已有文件和数据库，保留上一版本。

数据集和训练产物暂由服务器云盘保存。Worker 使用 D 盘独立云端接入目录，保留已有哈希缓存协议；模型基础权重可以只读复用现有固定版本缓存。缓存感知调度、OSS 和传输费用优化不在本轮实施。

## 远端环境

已只读检查：实际为 Debian 13.4、系统 Python 3.13.5、4核、约15GiB内存和40GB根盘，剩余约36GB，未见已有应用监听。现有系统 Python 保留。

用户已确认Docker Compose和具体安装清单。应用与PostgreSQL分别容器化，宿主安装Docker Engine/CLI、containerd、Buildx和Compose；数据库及应用虚拟环境均留在容器内。实际应用Python3.12.16，32个锁定Linux安装包离线安装，pip check及63项Linux后端测试已通过。实际配置见[运行与验收](./运行与验收.md)。

容器内采用专用应用权限，控制端不启用本机 Worker 快捷开关。首次管理员在受控终端创建，关闭网页初始化；原始密码、数据库连接凭据、节点凭据不写入公开文档、命令参数或访问日志。Compose私有环境文件与持久化数据由服务器权限保护，检查配置使用不输出值的校验方式。

## GPU 交接与基础训练

1. 先检查本机原 Worker 的活跃任务和设备占用。已有训练继续运行时等待完成；需停用项目推理服务时通过平台协作停止，确认结束后才释放资源。不停止其他应用或修改驱动。
2. 一个物理 GPU 同时只交给一个控制端调度。旧 Worker 暂停派发并确认无执行后停止，保留状态与缓存；新 Worker 使用独立目录、接入申请和凭据，不覆盖旧身份。
3. 云端生成接入申请，本机下载云端发布包构建的固定版本 Worker，验证摘要后注册，检查 CUDA、训练器、心跳及设备清单，再审核准入。
4. 在云端建立验收工作空间、训练额度及预置模型/数据。权限和配额设置写入操作记录；不更改本机已有账号策略。
5. 从云端页面提交一次小规模图像分类 GPU 训练。固定数据和参数，检查任务快照、文件摘要、真实 CUDA 设备、逐轮指标、日志序号和终态；下载并校验产物。
6. 训练结束后确认资源释放，页面可查看与刷新结果。本机旧服务不自动重启；云端 Worker 是否长期保留运行写入交接。

## 通过条件与故障处理

| 检查 | 通过依据 |
| --- | --- |
| 远端应用 | 实际 Linux 进程、页面与 API 同源可用，`/readyz` 返回正确迁移版本 |
| 数据持久化 | 独立数据库迁移成功；服务重启后账号、样本、任务和产物仍在 |
| 访问控制 | 未登录不能读业务数据；初始化关闭；来源和会话配置与入口一致 |
| Worker 接入 | 云端能看见本机真实 GPU、运行时、心跳及准入状态 |
| 跨机器训练 | 任务在 Linux 创建、在本机 CUDA 执行，指标回到云端 |
| 产物与释放 | 服务器保存实际产物及摘要，训练终态正确，设备恢复空闲 |

遇到依赖、迁移或训练错误，记录具体失败并停止相应变更，先保留日志和备份。恢复代码时不盲目回退数据库。Worker 失联仍保留执行占用，核查原进程后处理，不直接重新派发同一执行。

服务器、Docker安装、HTTPS和本机GPU接入均已验收。用户决定仅保留服务器备份，未将数据库或存储备份下载本机。登录密码不保存在仓库、部署包或公开文档；后续SSH使用已验证公钥。自助注册及智能辅助未包含在本次部署能力中。
