### 一期智能辅助的完成标准

**智能标注。** 用户选择数据版本、样本范围和标签规范，系统依据任务模态选择已授权的文本或视觉模型。返回结果先作为候选保存，支持逐条或批量复核、修改和拒绝。确认后发布新数据版本，记录样本、模型、提示词版本及采纳来源。文本分类和图像分类可作为首批标注场景；框、掩码、实体区间等按任务增加编辑器与格式校验，不能把任意视觉模型默认视为精确定位模型。生成标注不得静默覆盖原版，也不得混用测试集改善训练集。

**智能参数。** 输入来自已登记的任务模板、模型版本、数据统计、真实设备能力及允许引用的历史实验。输出逐项列出原值、建议值、理由和约束，允许部分采纳。服务端检查字段、类型、范围、模型兼容性和资源条件，用户确认后形成新配置。显存判断依据模板估算和实际设备信息，模型建议不能代替容量校验；不承诺固定参数一定提高准确率。界面提供易用模式与高级配置，不把所有参数和说明一次性铺开。

**智能日志。** 基于真实任务配置、故障事件和用户选定的日志片段解释问题，结果区分原始事实、模型推测、证据位置、排查步骤及建议动作。先用确定性规则识别已知错误，再由模型解释上下文；证据不足时提示缺少的信息。建议改参可以转成配置草稿，重跑、停止等动作仍走原有权限和确认流程，不执行模型生成的任意命令。

三项能力共用辅助请求和结果记录，区分处理中、待确认、已采纳、拒绝、过期、失败与取消等业务情况。采纳时重新检查关联版本和当前权限；配置、数据或资源条件已改变时拒绝直接应用旧建议。重复点击不会生成重复版本或重复作业。外部模型不可用时，人工标注、普通配置和训练仍可继续。

### 模型连接与数据外发

已确认外发方式为“工作空间授权 → 用户选定日志/配置统计/样本 → 脱敏与预览确认 → 服务端调用”。本次规划不发送任何真实项目数据，也不触发付费 API。

管理侧需要保存提供商、模型标识、接入地址、文本/图像/结构化输出等能力、调用权限、超时、限流及预算。凭据只在服务端受控存储，页面仅显示脱敏状态；与本平台推理 API KEY、Worker 接入凭据分别管理。接入地址须受管理员允许范围约束，内部服务可按批准的地址接入，避免任意地址探测。

预览确认绑定本次请求或选定批次的目的、提供商、数据版本和输入范围。扩大样本范围、改变提供商或输入版本时重新检查授权。密钥、密码等不得进入模型上下文；具体禁发字段、供应商保留政策、调用区域和预算在接入配置中确认。日志、样本和检索内容中的指令作为数据处理，不能获得业务操作权限。

提供商通过适配器接入。接口兼容不代表视觉、结构化输出、流式返回、工具调用和用量统计等能力相同，需要按实际模型验证。优先接通一家具备目标能力的 API，保留替换接口，不在一期同时维护大量提供商。

### 建议技术结构

沿用已讨论的 Python 与 FastAPI，控制平面采用模块化单体，计算平面为独立 Worker。模块按身份与授权、工作空间、数据、模型目录、训练、资源、监控、评估/推理、智能辅助划分，分别提供应用服务；不按模块数量提前拆成多个微服务。

业务逻辑供页面 API 与后续 Agent 工具共同调用。领域规则不依赖 HTTP 请求、某个大模型 SDK 或图形工作流框架。长任务由独立调度/执行进程处理，状态与待执行记录可靠持久化，避免依赖 API 进程内的临时后台任务。

- 正式业务存储建议使用 PostgreSQL，存储对象、版本、任务、执行、权限、辅助请求、采纳与审计记录。
- 文件访问通过存储接口封装。本机先使用 D 盘受控目录，后续按需要接入组织对象存储；业务代码不直接写死绝对路径。
- 任务队列先采用可恢复的持久记录与独立调度器；Redis、专用消息队列根据并发和部署需要再决定，不默认全套引入。
- Worker 注册、心跳、领取、执行、事件回传和资源清理使用独立协议。先完成本机 CPU、单 GPU，再接更多节点；个人设备优先承担独立作业，不把多机显存相加。
- 前端保留已确认的导航、配色和组件样式，增加统一数据访问层、异步状态及错误处理。框架迁移单独评估，不与视觉重做混在一起。
- 日志和指标采用可续传的事件与游标，前端通过 WebSocket 等方式订阅真实变化；断线后补取，浏览器关闭不影响训练。

保留四个清晰的适配边界即可：训练器、计算后端、外部模型提供商、存储。训练器说明支持的任务、数据契约、参数规则、运行时和资源条件，输出约定的事件、指标及产物；前端添加模型时绑定这些能力。第一期不提供任意代码上传执行或面向普通用户的训练器插件市场。

本机开发不依赖 Docker Compose，运行、数据、下载、缓存和日志优先放 D 盘；Linux 云服务器部署沿用相同配置与存储接口。新增数据库、依赖和系统服务安装均先确认。

一期验收使用同一批固定数据、任务和故障场景。分别统计结果格式合格率、人工标注一致性/修改量、参数建议的可执行性、日志诊断的证据正确性，以及任务与资源恢复结果；具体质量门槛在基准集确认后填写，不预先编造准确率或性能提升。API 超时/限流、非法输出、重复提交、过期建议、错误权限、Worker 失联、浏览器断线和控制端重启应有自动化或可重复验证。

### 后续 Agent 设计

后续目标为面向训练业务的受控助手：理解目标、读取获授权上下文、制定步骤、调用平台能力、等待确认，并保留可恢复的执行记录。先用一个 Agent 配合确定性工作流验证价值，多 Agent 协作按真实需要扩展。

| 模块 | 职责与边界 |
| --- | --- |
| 工具目录 | 将已有应用服务包装为带类型的业务操作，登记输入输出、所需权限、影响对象、风险、幂等与超时；不直接开放数据库、任意 SQL 或系统命令 |
| 会话与上下文 | 保存用户目标和当前步骤，按权限取必要的数据概况、任务、日志和模型说明；控制上下文大小，实时状态通过工具查询 |
| 工作流与执行 | 管理计划、工具调用、等待、超时、取消和检查点；恢复时依据操作回执及幂等标识核对，避免重复提交作业或重复采纳 |
| 记忆与知识 | 会话记忆保存多轮上下文；项目记忆保存经确认的标签规范、业务约束与有效经验；用户偏好单独保存；知识库保存获准的操作文档与训练说明 |
| 授权与审批 | 查询、草稿写入、真实执行与破坏性操作分别控制。启动训练、占用 GPU、发布服务、停止和删除按动作授权并确认，不由一次宽泛同意永久放行 |
| 审计与评估 | 保存模型/提示词版本、工具参数、外发范围、确认依据、用量和真实结果；评估越权、幻觉、失败恢复、记忆误用及任务完成情况 |

工具可以先覆盖数据概况、模型检索、可用资源、任务状态、日志、指标和结果比较；再加入创建配置草稿、启动预标注、提交训练及发布服务等操作。页面与工具共用同一份权限、兼容性、预算和业务校验，不能绕过现有服务直接写库。

记忆需关联工作空间、可见范围、来源、版本、确认时间、有效期及撤销/删除状态。经验候选经用户确认后进入长期记忆；“某数据集上成功的配置”必须保留适用条件。任务运行状态、空闲显存与可用配额读取实时业务数据；密钥不进入记忆。跨项目检索仍按当前用户权限过滤。Agent 取到更多数据并准备外发时，也须遵守已确认的工作空间授权与预览规则。

示例一：用户提出“用新评论数据训练咨询分类器”，Agent 查询数据与模型 → 生成处理/标注及训练方案 → 用户确认 → 调用既有配置与提交服务 → 跟踪结果并解释指标。示例二：训练失败后，Agent 读取获准日志和配置 → 解释证据 → 提出修订草稿 → 用户确认后创建新任务。两个流程都保留原始版本和用户决策。

框架上可以评估 LangGraph 等支持持久状态和人工介入的实现，但一期不依赖其特定接口。MCP 可作为后续对外工具协议适配层，工具、资源和提示词复用平台能力；它不承担平台权限、资源调度、记忆治理和训练执行的业务职责。本轮不安装 Agent 框架或开放外部工具服务。

### 前端调整范围与创新验证

已确认的深青绿主操作、中性色主体、蓝色详情入口、微圆角和菜单交互继续保留。新增能力围绕业务入口设计：训练向导中提供推荐参数；任务日志中提供解释；标注进入独立工作区；管理侧增加模型连接和资产维护。复杂编辑使用独立页面，普通新增/修改使用弹窗，具体布局制作前再确认。

新手路径先提供目标、模板和少量必要选项，高级参数按需展开。解释与建议放在用户主动打开的正常字号内容中，不恢复名称下灰色小字和整页冗余导语。真实页面补上传/处理中/失败/无权限/无可用资源等反馈，已上线能力与未支持能力明确区分。

## 2026-10-16 智能辅助与训练故障处理

新增方向为调用外部大模型 API，提供日志解释、训练参数推荐和辅助标注。已确认建议经人工确认后可以应用到新配置或新数据版本；外发数据范围保持待确认，完成相应授权前不发送真实任务日志或数据样本。具体接入商、模型能力及本期验收范围待确认。以下内容作为需求补充草案；当前没有接入真实外部大模型，也未据此修改已提交的 SRS、SPEC、用例和模型。

### 外部大模型辅助

| 待补用例 | 输入与处理 | 输出及确认要求 |
| --- | --- | --- |
| 管理大模型连接 | 授权管理员配置接入地址、模型、凭据及支持能力，检查连通性 | 连接状态与失败原因；凭据脱敏展示，调用权限、限额和允许发送的数据类别分别配置 |
| 解释日志与诊断故障 | 授权用户选择任务、失败事件和必要日志片段，发送前检查范围并脱敏 | 展示已采集事实、对应日志位置、模型推测、排查步骤和可选处理建议；证据不足时明确说明 |
| 推荐训练参数 | 使用任务类型、模型及数据版本、设备能力、参数限制和获准历史实验 | 生成参数草案，逐项展示原值、建议值和理由；模板校验通过且用户确认后，才用于新任务配置 |
| 辅助标注 | 用户选定数据版本、样本范围、标签规范及支持该模态的模型 | 生成候选标签；支持逐条修改或批量复核，确认后发布新标注版本，保留样本、模型和审核来源 |
| 查看并处理辅助结果 | 查询调用、输入版本、建议、采纳情况及执行结果 | 可采纳、部分采纳或拒绝；重复确认保持幂等，过期建议须重新核对关联版本与当前权限 |

已确认的执行边界为“建议预览 → 人工确认 → 服务端权限与业务校验 → 创建新配置或新版本”。运行中的训练配置保持不变；模型生成的命令不直接执行，停机、删除、安装依赖、提权及付费资源开通仍按独立授权处理。其他可执行操作须另行确认。

外发前按工作空间授权，只提供本次任务所需的日志、配置或获准样本。凭据、密码及不必要的个人信息不进入模型输入；敏感数据的外发许可、输入预览、保留策略和撤销方式需进一步确认。日志和样本内容作为待分析材料处理，其中的指令不获得平台操作权限。输出格式、参数范围、标签与定位坐标由确定性规则检查。

外部接口鉴权失败、限流、超时、额度不足、结果格式错误或人工取消时，仅影响对应辅助请求。记录可理解原因并保留人工操作路径；训练、标注和普通数据处理继续按自身规则运行。调用重试须有次数、超时和费用上限，切换提供商前重新核对数据授权。不得根据模型自报分数推断诊断正确率。

### 训练故障处理补充

所有异常至少记录任务及执行编号、发生阶段、错误类别、源时间、原始证据、当前处理状态、资源占用和可执行的下一步。训练状态、节点健康状态、辅助请求状态及资源清理状态分别记录，界面保留最后一次确认时间。大模型解释关联原始证据，平台事实和处理权限由实际事件与业务规则确定。

| 场景 | 状态与处理草案 | 恢复边界 |
| --- | --- | --- |
| 参数、权限或模型数据不兼容 | 受理前拒绝并定位字段或限制，保留草稿；执行前复核失败则记录任务失败 | 修正后重新校验；不会无限重试无效配置 |
| 资源暂时不足或可用配额已占满 | 合法任务排队，显示具体阻塞原因；请求本身超过硬性上限则拒绝 | 有资源时重新检查权限、预留并派发 |
| 模型或数据下载超时、环境准备失败 | 记录启动准备阶段和原始错误；网络类故障可有限重试，依赖不兼容与校验和错误停止准备 | 重试范围和次数待定；无执行启动确认时不显示已开始训练 |
| 数据损坏、标签或尺寸不合法 | 定位文件、样本及字段，失败后保留数据版本和错误报告 | 修正为新数据版本后创建新任务 |
| 显存不足 | 保留错误、设备和参数证据；结束失败进程并确认资源清理 | 提供批大小、序列长度、梯度累积等候选调整；用户确认后创建新任务，不自动反复启动 |
| Loss 非有限值或训练进展异常 | 按模板明确的检测规则告警或终止；区分数值错误、性能缓慢和真正无进展 | 连续异常次数、进展超时及动作待模板确认；不由大模型单独判定训练应当停止 |
| Worker 心跳丢失或节点掉线 | 标记联系异常并展示最后确认状态，停止新派发，保留资源占用并核查实际进程 | 核实原进程结束或隔离有效后再安排恢复，防止同一任务重复运行 |
| 浏览器断线或监控推送中断 | 训练继续；界面提示采集或连接异常，不能展示为最新确认的运行信息 | 重新查询状态，日志按游标续传，不重新启动训练 |
| 训练结束后产物上传或校验失败 | 区分训练进程完成与交付完成，记录产物处理阶段；保留本地产物并有限重传 | 必要产物完整前不登记成功，不重复训练；重传用尽后记录失败和可恢复位置 |
| 停止超时或资源释放失败 | 保持停止中或资源待清理记录，告警并隔离相关资源 | 强制终止须授权并留痕；确认进程结束及清理结果前，不假报已停止或资源空闲 |
| 控制平面重启 | 从持久记录恢复，再与 Worker 核对任务、执行和资源预留 | 识别已有执行，避免重新派发同一次任务 |
| 外部计算平台调用结果不确定 | 保存提交标识、错误和已知外部执行编号，核查远端实际执行 | 无法确认未创建任务前不盲目重提，避免重复执行或重复付费 |

恢复动作区分为连接恢复、原操作重试、重新训练和检查点续训。连接恢复和产物重传保留原任务；重新训练创建关联原任务的新任务。检查点续训仅对已声明支持的模板开放，创建带来源关系的新任务，并检查模型、数据、运行环境和检查点完整性。单独的模型权重不足以证明可恢复完整训练状态；优化器、调度器、步数等信息按训练器要求保存。

异常验收应使用可控场景逐项验证：非法配置、资源被占用、损坏数据、受限显存、Worker 断线、监控断线、存储拒写、停止超时、控制端重启和重复事件。核对状态、日志、原始证据、资源占用、重复执行及恢复结果；诊断建议的正确性与训练恢复成功分别统计，不预填效果数据。

### 后续高级能力与创新候选

- 大模型辅助数据增强：生成或改写候选样本，检查格式、标签与重复，人工复核后形成独立版本，保留原样本和生成来源；验证集与测试集的使用边界需单独约束，避免评估数据泄漏。

## 服务与管理

- 服务创建和在线测试只生成本地演示记录与模拟响应；接口地址为示意，未部署推理进程、鉴权、限流、扩缩容或真实调用统计。
- API KEY 页面只生成浏览器演示字符串并保存脱敏标识，未签发服务端凭据，也不具备鉴权、有效期、轮换或撤销传播能力。
- 登录注册仅验证页面流程；演示账号为固定凭据，新注册账号的密码摘要保存在浏览器本地。需要服务端身份认证、密码策略、找回密码、会话管理与安全审计。
- 用户组、个人允许/禁用权限、有效配额、菜单访问和操作记录都由浏览器本地计算或保存。需要服务端统一执行权限与配额校验，防止绕过前端。
- 资源监控和统计面板使用静态或演示状态；需要接入指标采集、实时任务队列、告警及历史统计。
- 管理端数据、模型、作业视图目前以查看和跳转为主；正式版本需增加审批、版本治理、任务终止/重试、异常处理与审计。
- GPU 接入命令是不可执行的占位文本，节点登记及硬件探测都是模拟。需要可信代理、一次性令牌签发、通信认证、硬件采集、连通性校验、节点审核、状态心跳、资源隔离与故障恢复。不要将页面命令用于真实服务器。
- 系统设置只影响本地演示数据；需要持久配置、权限约束和变更审计。
- 需要规划后端 API、数据库与对象存储、训练运行环境和非 Docker Compose 的本地开发方案，并补充部署、备份与故障处理说明。
