# 推理任务约束修复

## 问题与范围

公开短信实验通过调用端手工附加分类指令并限制4个新Token；页面只发送短信正文，服务默认自由生成，用户会得到聊天回复或拒绝句。LoRA权重没有携带部署所需的任务指令和固定标签配置。

本次修复保存显式部署契约，复用已有模型与权重，保留历史任务和结果。分类模式保证输出属于指定标签集合；预测是否正确继续由模型和独立测试判断。普通生成模式继续提供开放文本输出。

## 设计

在任务config下新增可选inference对象：mode为generate或label，instruction为任务指令，labels为2～32个不重复的短标签。仅Qwen在线服务使用该配置。已有客户端未传配置时保持原有自由生成协议；页面部署时根据固定训练数据提供指令及候选标签，用户可编辑后确认。候选只提供建议，实际部署值明确保存到快照。

job-options为可用Qwen版本返回建议的instruction及短输出候选。仅读取模型所引用的训练数据版本并验证SHA256；多指令、长回答或缺失数据不推断固定标签。后端拒绝空标签、重复标签、控制字符及无效模式。文本/图像分类器不接受Qwen推理配置。

Worker将部署指令与正文按训练模板组成提示；标签模式使用Token前缀树，逐步屏蔽不属于标签路径的Token，完整标签后只允许EOS。输出预算不足、输入Token超限、提前取消或异常输出返回明确错误，不将任意聊天文本映射为标签。生成模式按Token预算正常生成。

Worker运行时上报inference_contract_version=1；旧版本默认为0，调度器不派发带inference配置的服务。控制端再次校验label属于部署集合、text与label一致；越界回执归为明确失败，相同失败重传保持幂等。

调用API仍只需text或image_base64，任务指令不由调用者重复附加。标签响应同时提供label和text（同一标签），兼容已有text读取。max_new_tokens继续作为上限；分类需要覆盖完整标签和结束Token。页面显示分类标签，普通生成显示文本。

页面提交未保存推理配置的旧Qwen服务草稿时，先打开配置弹窗确认输出方式，覆盖旧服务“重跑”路径。旧客户端API保留自由生成兼容，页面详情明确显示其输出方式。

## 实施与验证

1. 添加复现测试，确认分类指令未合入和输出不受约束的旧行为。
2. 更新API配置、部署表单、快照、Worker解码并验证生成模式兼容。
3. 验证原始短信、正常短信、要求改为聊天的输入、长输入和Token预算边界；不手工拼接分类指令。
4. 切换前备份，核对运行中任务。更新Worker会影响同节点服务，先确认切换范围，再停止并按原模型重建服务，保留旧记录。
5. 原128条自由生成实验结果保持不变，修复后测试单独记录，明确区分约束协议与分类准确率。

参考：[Transformers4.57生成接口](https://huggingface.co/docs/transformers/v4.57.0/main_classes/text_generation)、[Qwen3模型说明](https://huggingface.co/Qwen/Qwen3-0.6B)。不新增依赖或下载权重，不修改系统环境。
