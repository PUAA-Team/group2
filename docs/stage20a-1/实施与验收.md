# Stage 20A-1：用户自助找回/重置密码

分支：`lx/stage20a-1-password-reset`（基线 `lx/stage19b-3-login-rate-limit`，本地 0591570，未合并 main，未部署，未推送）。

## 完成范围

### 1. 管理员签发一次性密码重置码
- [auth.py](../../backend/src/model_platform/api/auth.py)：新增 `POST /api/v1/auth/password-reset-codes`（管理员，`users.manage`）。按账号签发 8 位重置码（无歧义字符表，去掉易混淆的 `0/O、1/I/L`），明文码只在本次响应里返回一次，库里只存 HMAC-SHA-256 摘要（`security.hmac_digest`，密钥取服务端 CSRF 密钥）；签发新码时作废该用户此前未使用的旧码，同一时间只有一个有效码；审计 `auth.password.reset_code.issue`。
- 未知账号返回 404 `NOT_FOUND`（管理端接口，不涉及用户枚举）；非管理员返回 403。

### 2. 用户凭码自助重置密码
- [auth.py](../../backend/src/model_platform/api/auth.py)：新增 `POST /api/v1/auth/password-reset`（公开接口）。账号 + 重置码 + 新密码（至少 12 位）即可重置；码默认 15 分钟过期（`MT_PASSWORD_RESET_CODE_MINUTES` 可配，配置见 [config.py](../../backend/src/model_platform/config.py) 的 `password_reset_code_minutes`），一次有效；重置成功后改密码、标记码已使用、踢出该用户全部历史会话，并清除账号与当前 IP 的登录限流计数；审计 `auth.password.reset_by_code`。
- 未知账号、停用账号与错误/过期码返回同一 400 `INVALID_RESET_CODE`，不泄露账号是否存在；猜码失败计入账号桶（19B-3 的账号维度滑动计数），15 次失败即锁定账号 15 分钟；但已锁定的账号仍可凭有效码重置，重置即是锁定的恢复路径。

### 3. 表结构
- 迁移 `0016_password_reset_codes`（注意：dev-plan 原文写的是 0014，但 0014/0015 已存在，本迁移顺延为 0016）：新建 `password_reset_codes` 表（`id / user_id / code_digest / expires_at / used_at / created_by / created_at`），`code_digest` 唯一；SQLite 升降级往返已验证通过。
- 模型见 [models.py](../../backend/src/model_platform/models.py) 的 `PasswordResetCode`；`serialize()` 的屏蔽字段已包含 `code_digest`，摘要不会随接口序列化外泄。

### 4. 前端
- 登录页新增“忘记密码”入口（`#/reset-password`），重置表单含账号、重置码、新密码与确认密码（[auth.js](../../frontend/live/pages/auth.js)）；未登录路由放行 `/reset-password`，已登录访问时跳回首页（[app.js](../../frontend/live/app.js)）；提交后提示“密码已重置，请使用新密码登录”并回到登录页（[events.js](../../frontend/live/events.js)）。
- 用户管理页新增“生成重置码”操作，签发的码只显示一次，可复制、可关闭（[admin.js](../../frontend/live/pages/admin.js)、[administration.js](../../frontend/live/administration.js)），与邀请链接的展示方式一致。

### 5. 说明与边界
- 本阶段新增 2 个接口，OpenAPI 同步导出到 [openapi.json](./openapi.json)（146 个路径，上一阶段 144 个）。
- 重置码有效期与账号桶阈值均为固定配置，未做管理端可配；重置码只通过管理员当面/站内转交，未接邮件或短信通道。
- 直接改密码的管理端接口（`POST /admin/users/{id}/password`）保持不变，与本次自助重置并存。
