# Stage 21A：空间自治与团队治理设计稿

## 1. 背景与定位重划

当前版本中，平台权限几乎全部收口在全局系统管理员（`is_admin=True`）手中，工作空间所有者（`workspace.owner_id`）仅能维护成员名单、开关智能辅助授权以及修改/删除空空间，缺乏团队 Leader 自治管理人、卡、额度和账单的能力。

Stage 21A 将 **“平台级治理”** 与 **“空间级自治”** 明确分层：

| 治理维度 | 平台系统管理员（`is_admin=True`） | 空间管理员（`owner_id` 或 `role="admin"`） |
| :--- | :--- | :--- |
| **物理机器与节点** | 跨空间划拨节点（`workspace_id`）、节点准入审批（`approved`）、全局硬件查看 | 管理**已归属本空间**的设备用途（训练/评估/推理/共享）与本空间成员设备白名单 |
| **人员与身份** | 创建/停用全平台账号、配置用户组、全局基础权限与个人禁用 | 邀请/审批本空间成员、设置空间内角色（`admin`/`editor`/`annotator`/`viewer`）、转让所有权 |
| **资源配额与预算** | 配置用户组配额/共享预算、配置**空间总预算**（`WorkspaceBudget`） | 在不超过空间总预算的前提下，为本空间成员配置**空间内子配额** |
| **运营与审计** | 全平台统计面板、全平台资产/作业/审计查询 | **本空间**成员用量账单（存储、GPU 时长、Token 消耗）与本空间审计视图 |

---

## 2. 数据模型与迁移设计（`0017_workspace_governance`）

### 2.1 `memberships` 表扩展
在 `Membership` 模型（[models.py](../../backend/src/model_platform/models.py)）新增可选子配额字段：
- `role: Mapped[str]`：支持 4 种角色：
  - `admin`：空间管理员（可管理成员、邀请、空间内设备策略、成员子配额、查看空间账单；不可删除空间或转让所有权，后两项仅 `owner_id` 或平台管理员可操作）。
  - `editor`：研发成员（可读写数据、训练、评估、模型、部署服务）。
  - `annotator`：标注员（仅可查看数据集、在线标注与样本预览，禁止写模型、提交训练或部署服务）。
  - `viewer`：只读成员。
- `quota: Mapped[dict | None] = mapped_column(JSON, nullable=True)`：空间成员子配额覆盖，例如 `{"gpu_count": 1, "concurrent_jobs": 2, "storage_gib": 20}`；`None` 或缺省键表示不额外限制（仍受平台配额与空间总预算约束）。

### 2.2 新增 `workspace_budgets` 表
参考 `GroupBudget`（[governance_models.py](../../backend/src/model_platform/governance_models.py)），新增 `WorkspaceBudget`（继承 `Timestamp, Revision, Base`）：
- `id: Mapped[str]`（主键，外键指向 `workspaces.id`）
- `value: Mapped[dict]`（JSON：`{"gpu_count": int | None, "concurrent_jobs": int | None, "storage_gib": int | None}`）

## 3. 核心权限、配额与设备自治规则

### 3.1 `workspace_access(db, user, workspace_id, action)` 判定升级
1. **成员准入**：非 `is_admin` 用户必须存在 `Membership` 记录。
2. **角色能力矩阵**：
   - `viewer`：禁止所有 `.write`、`.manage`、`.invoke`、`.use` 后缀动作。
   - `annotator`：仅允许 `datasets.read`、`datasets.write`（限于标注读写/预览，**禁止**删除数据集或发起增强/清洗发布，或按模块细化）、`assistants.use`（若空间政策开启）；禁止 `training.*`、`models.write`、`services.*`、`members.manage`、`resources.manage`。
   - `editor`：允许常规研发读写动作，禁止 `members.manage`、`resources.manage`（除非同时具有 `admin` 角色）。
   - `admin`（或 `workspace.owner_id == user.id`）：允许空间内 `members.manage` 及本空间设备策略配置（`resources.manage` 仅限本空间范围）。
3. **个人/用户组全局边界仍优先**：无论空间角色多高，若用户在平台层面的 `effective_policy` 中缺少对应权限（或被显式 `deny_actions` 禁用），依然返回 `403 FORBIDDEN`。

### 3.2 三层资源配额收敛
在任务提交/调度（`scheduler.py` / `jobs.py`）和文件存储扣额（`budgets.py`）中，成员在某空间的实际可用上限按以下规则生效：
1. **个人有效上限**：`min(平台个人/组配额, 空间成员子配额)`（子配额未设置时不收紧）。
2. **空间总盘子上限**：若空间配置了 `WorkspaceBudget`，统计本空间当前 `Execution(finished_at IS NULL)` 占用并发/GPU 及 `StoredObject` 空间总字节数，超出则返回 `409 BUDGET_EXCEEDED` / `413 WORKSPACE_STORAGE_LIMIT`。

### 3.3 本空间设备自治权下放
- **平台管理员专属边界保留**：`POST /admin/enrollments`、节点准入审批 `approved`、节点跨空间迁移 `workspace_id` 变更，继续硬性要求 `actor.is_admin`。
- **空间内设备策略下放**：`GET/POST /api/v1/workspaces/{workspace_id}/devices/{device_id}/policy`（及兼容原 `/resources/devices/{device_id}/policy` 校验）放开给本空间 `admin` / `owner_id`：
  - 校验设备所属节点必须属于该 `workspace_id`；
  - 空间管理员仅可配置本空间成员（`allow_users`/`deny_users` 必须属于该空间成员）与设备用途 `purpose`（`shared`/`train`/`evaluate`/`service`）。

## 4. 新增与改造 API 契约

1. **成员角色与子配额 / 所有权转让**：
   - `POST /api/v1/workspaces/{workspace_id}/members`：`role` 扩展支持 `admin | editor | annotator | viewer`；新增可选 `quota` 字段（仅空间 `admin`/`owner` 或平台管理员可设置）。
   - `POST /api/v1/workspaces/{workspace_id}/transfer-owner`：请求体 `{"user_id": "..."}`，仅当前 `owner_id` 或平台管理员可操作，将 `owner_id` 转让给本空间内已启用的 `admin`/`editor` 成员，并强制原所有者保留 `admin` 角色（需带 `If-Match` 乐观锁）。
2. **空间总预算（平台管理员）**：
   - `GET /api/v1/admin/workspaces/{workspace_id}/budget`
   - `POST /api/v1/admin/workspaces/{workspace_id}/budget`（需 `If-Match` / `revision`）
3. **空间内设备策略与成员列表（空间管理员）**：
   - `GET /api/v1/workspaces/{workspace_id}/devices/{device_id}/policy`
   - `POST /api/v1/workspaces/{workspace_id}/devices/{device_id}/policy`
4. **空间用量统计与成员账单（空间管理员）**：
   - `GET /api/v1/workspaces/{workspace_id}/governance/summary`：返回本空间总预算 vs 实际占用（并发、GPU、存储）、按成员分组的存储占用、运行中/已完成任务数、GPU 预留时长及已确认智能辅助 Token 消耗。

## 5. 前端界面改造（`frontend/live/`）

1. **用户空间（`/space`）升级为空间治理中心**：
   - 成员列表新增“空间子配额”列与“转让所有权”按钮，角色下拉支持“空间管理员 / 研发成员 / 标注员 / 查看者”。
   - 新增“空间配额与成员账单”卡片：展示本空间总预算进度条，以及按成员统计的存储/GPU 时长/Token 明细表。
2. **资源监控与节点详情（`/monitor`）**：
   - 对本空间管理员开放设备“用途与白名单”弹窗入口（此前仅全局 `is_admin` 可见），列表仅拉取本空间成员作为白名单候选项。
