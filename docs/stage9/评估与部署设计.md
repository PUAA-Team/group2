# 评估与部署设计

训练成功后生成模型版本，来源为平台产物引用，固定父任务、哈希与训练器。模型评估选择可用模型版本及固定数据版本，提交到 Worker；分类返回 accuracy、macro F1 与混淆矩阵，指令模型返回响应部分 token loss。跨实验比较必须展示数据版本与指标口径。

在线服务是一类持续占用设备的执行。Worker 下载产物并加载模型成功后报告就绪；控制端保存调用请求，Worker 获取、推理并回传结果。服务停止后收到进程退出回执才释放设备。主服务器无须访问 Worker 端口。首版本机轮询用于内部联调，适配大量并发和 WebSocket 推送列入后续计划。

服务测试通过登录会话；API KEY 使用独立 Bearer，只授权指定工作空间的指定服务。密钥仅生成时显示一次，服务端保存哈希、创建者、过期时间与撤销状态。调用时同时检查创建者当前授权、成员角色与服务状态；密钥不能访问资源、训练或管理 API。

浏览器接口：`/api/v1/workspaces/{id}/jobs` 的 kind 为 evaluate/service，`/jobs/{id}/calls` 提交测试，`/calls/{id}` 读取结果；`/service-keys` 创建、列表与撤销。外部 `/api/inference/v1/services/{id}/predict` 接受 API KEY，返回可轮询请求 ID；`/calls/{id}` 查询结果。首版异步协议避免长连接占满服务线程，客户端应设超时。

Worker 就绪和调用结果均按执行与请求 ID 约束。输入限定文本或有界 Base64 PNG/JPEG；限制文本长度、图片体积及生成 token 数。服务故障将未完成调用标记失败；请求结果去重保存在本地，通信重试不重复生成。
