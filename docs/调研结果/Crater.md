## Crater

Crater 是 Kubernetes + Volcano 上的共享 AI 计算集群控制面。源码包含 React 前端、Go 后端、CLI、Helm Chart、Grafana 面板和完整文档。

![Crater 架构](https://2bpic.oss-cn-beijing.aliyuncs.com/architecture.webp)

| 层       | 设计                                                         |
| -------- | ------------------------------------------------------------ |
| 用户入口 | Web、CLI、HTTP API、面向 Agent 的命令技能                    |
| 控制面   | 用户、账户、队列、配额、作业、服务、镜像、数据集、模型、审批、计费、审计 |
| 执行层   | Kubernetes Workload、Volcano、GPU/vGPU/RDMA、Pod、Service、PVC、Ingress/NodePort |
| 可观测层 | Prometheus/Grafana、Pod 日志、Kubernetes 事件、GPU 分析、操作记录 |

### 完整流程

**训练**

1. **登录并选择账户**

   - 用户可处于公共账户或团队账户。
   - 账户决定队列、配额、优先级、可用资源和计量归属。

2. **准备代码和数据**

   - 文件上传到个人/账户/公共空间。
   - 已有目录可登记为只读数据集或模型。
   - 也可从 HuggingFace/ModelScope 发起后台下载。

3. **选择运行环境**

   - 选择公共镜像、个人镜像或制作新镜像。
   - 镜像固化 CUDA、框架和依赖，避免每次任务重复安装。

4. **创建作业**

   - 选择自定义批作业、Jupyter/WebIDE、PyTorch DDP、TensorFlow PS 等类型。
   - 填写名称、镜像、Shell、启动命令、工作目录。
   - 选择 CPU、内存、GPU 型号与数量；高级项支持 vGPU、RDMA、节点包含/排除。
   - 挂载个人文件、账户文件、公共文件、数据集或模型；配置容器挂载路径。
   - 可配置环境变量、端口转发、通知和普通/回填调度类型。

   ![image-20260928171214622](https://2bpic.oss-cn-beijing.aliyuncs.com/image-20260928171214622.png)

5. **准入和排队**

   - 先校验账户、用户资源上限、下载/计量状态和任务类型。
   - 作业进入预排队；条件满足后提交给 Volcano/Kubernetes。

6. **运行与诊断**

   - 列表显示状态、账户、用户、资源、节点、开始/结束时间。
   - 详情显示 Pod、内网 IP、分配节点、申请资源、YAML、资源监控。
   - 支持 Web 终端、日志、Kubernetes 事件、外部访问。

7. **结果保存**

   - 输出写入挂载目录，任务结束后仍保留。
   - 可将结果目录登记为模型，供后续训练或推理挂载。

8. **失败处理**

   - 通过事件区分调度失败、镜像拉取失败、挂载失败和程序错误。
   - 通过 Pod 日志定位训练代码错误。
   - 可调整配置后重新提交或从模板复用配置。

训练表单把核心项放在主区，把数据挂载、环境变量、观测面板和高级设置放在侧区，适合本项目的页面布局。

![Crater 训练任务配置](https://2bpic.oss-cn-beijing.aliyuncs.com/filljobinfo.webp)



**推理**

1. 在模型页下载或登记模型目录。
2. 选择 vLLM/DeepSeek 等作业模板。
3. 模板预填镜像、启动命令、模型挂载、GPU 型号和数量。
4. 启动后在详情页读取内网 IP 和服务日志。
5. 配置 Ingress/NodePort 外部访问。
6. 通过 curl 或 Open WebUI 调用 OpenAI 兼容接口。

3. 数据集下载

支持直接从modelscope、hugging face下载

![image-20260928171040803](https://2bpic.oss-cn-beijing.aliyuncs.com/image-20260928171040803.png)

这个系统做的更像文件/云盘系统，咱们可以做的更简便。

- 数据集/模型主要是提供一种只读的文件

- 数据集/模型表记录逻辑路径、来源、版本、状态、引用数、大小、校验和、所有者、可见范围。

- 从 HuggingFace/ModelScope 下载采用后台 Job。相同仓库 ID 复用公共资源，避免多人重复下载。

- 管理员可设置并发下载数、滚动窗口成功数和白名单。

- 平台可以为每个用户配置两类下载额度：同时处于“等待中”或“下载中”的任务数，以及滚动时间窗口内成功完成的下载数。创建新的 Kubernetes 下载 Job 时会立即预占一个滚动窗口名额，防止下载尚未完成时连续提交大量任务。

  创建新下载、重试失败任务和恢复暂停任务都会按实际操作用户检查额度。任务成功后，预占记录从实际完成时间开始计入滚动窗口；失败、暂停、删除或 Job 提交失败会释放预占名额，不计入成功下载数。

下载额度

- **启用下载额度限制**：控制是否执行额度校验。关闭时仍记录每个 Job 的预占、成功和释放状态。
- **最大同时下载任务数**：每个非白名单用户同时处于 `Pending` 或 `Downloading` 的任务上限。
- **滚动窗口（小时）**：从当前时刻向前统计成功下载的时间范围，不是固定整点区间。
- **窗口内最多成功下载数**：成功任务按实际完成时间计数；正在运行的 Job 会预占一个窗口名额。
- **白名单**：白名单用户跳过并发和滚动窗口校验。平台管理员不会自动豁免，必须显式加入白名单。

管理员可以在“平台设置”中的“Pod 带宽限制”分别控制模型下载、Volcano 作业入站和出站带宽。作业配置同时覆盖普通作业与回填作业。

- **模型下载带宽**：写入 model-dl Pod 的入站 bandwidth annotation，限制下载数据进入 Pod 的速率。
- **作业入站带宽**：限制流入普通与回填作业 Pod 的速率。
- **作业出站带宽**：限制从普通与回填作业 Pod 发出的速率。

预排队用于在作业进入集群调度前做统一准入控制。管理员可以在管理端的“更多 / 预排队”页面调整提交开关、激活节奏和用户资源限制。

预排队策略

- **允许提交回填作业**：开启后，用户可以创建回填作业。回填作业只使用当前空闲资源，且不支持申请锁定。
- **启用用户资源限制**：开启后，作业提交与激活会检查用户在目标队列中的资源占用上限。
- **普通作业等待容忍时间**：普通作业进入等待状态后，超过该时间仍未激活时会按当前策略继续处理。
- **激活扫描间隔**：后台按该间隔扫描可激活的预排队作业。
- **每轮最大激活数量**：限制单轮扫描最多激活多少个作业，避免一次性放量过大。

用户资源限制

每条限制绑定一个队列，只对该队列中的作业生效。建议为 GPU 队列单独配置限制，CPU 队列按业务需要启用。

- **启用状态**：关闭后保留配置但不参与检查。
- **候选作业数量**：限制单个用户在该队列中可以同时进入候选激活集合的作业数。
- **CPU / 内存上限**：留空表示不限制该资源；填写后按用户当前占用与待提交作业请求量合并计算。
- **加速卡上限**：按型号和数量成对配置。未配置的型号不受该条规则限制。
