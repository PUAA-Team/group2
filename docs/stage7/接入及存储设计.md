# 接入及存储设计

## 控制端与 Worker

管理员生成绑定工作空间的接入申请；获授权成员可为自己的空间申请。接入码短期有效且只用于注册，Worker 先生成并私密保存自己的长期凭据，再提交其摘要及稳定安装标识。控制端仅存摘要。相同申请和凭据摘要的网络重试返回同一节点，不生成重复资源；更换安装标识或摘要不能重用申请。

节点主动注册、心跳、领取任务和回传事件；控制端在响应中发送探测或停止意图。注册包含 CPU、内存、NVIDIA UUID/显存/驱动，以及训练 Python 的实际能力。硬件存在和可执行 CUDA 分别记录，不能将检测到显卡直接当作训练运行时可用。自动发现是 Worker 自检并上报，首版不扫描局域网或自动 SSH 到其他机器。

新节点默认待审核，管理员可在创建本机申请时选择自动准入。节点绑定空间，空闲时可调整分配；跨空间共享池后续单独扩展。暂停只停止新派发，已运行任务继续；活跃任务未确认结束时禁止直接撤销凭据并释放资源。

## 接入命令

提供 Windows PowerShell 和 Linux shell 版本。命令下载版本固定的 Worker zipapp，验证 SHA-256 后运行；普通 Python 运行注册和心跳，训练可使用已装 PyTorch 的独立解释器。默认不全局安装库，也不修改驱动、系统服务或防火墙。

长期 Worker 凭据不进入命令。限时接入码只在创建时返回一次，前端内存持有；显示区域默认遮蔽，复制命令才包含完整短期码，不写浏览器存储、审计或截图。节点凭据不能用于用户登录、管理 API 或任意数据下载。

本机快捷接入由显式开发开关开放，只对回环请求和管理员启用，使用配置的解释器与 D 盘目录；不接收任意待执行命令。远程机器运行复制指令时使用能访问的主服务器地址，生产使用 HTTPS。当前 8000 仍只监听回环，不自动改防火墙或绑定公网；局域网监听由部署者明确配置。

Docker 模式按同一 Worker 协议。只有提供实际镜像地址后才生成拉取/运行命令；同时交付 Dockerfile。NVIDIA Container Toolkit、镜像构建及 Linux GPU 映射分别验收，不用本机原生 Python 成功冒充容器成功。

## 文件归属与传输

主服务器保存不可变数据版本及模型产物，任务固定版本号、大小和 SHA-256。Worker 领取执行后取得自己的文件清单，凭节点身份和有效执行访问文件。接口同时校验节点、执行、空间与对象关联，不能传任意磁盘路径或读取其他作业文件。

文件下载先写临时文件，校验后按内容摘要放入本地缓存；命中缓存仍校验摘要。控制端路径不下发为跨机器共享路径。失败留下可重试记录，不能把半文件当作可训练内容。训练产物上传并通过清单及摘要校验后才能成功，主服务器以后可把相同存储接口替换为对象存储/限时地址。

Qwen 的公开基础权重暂按批准的仓库及固定提交下载到 D 盘缓存，禁止远端自定义模型代码。适配器产物回传主服务器，推理端按清单重新获取相同基础版本。未来支持主服务器集中基础模型文件，再分发至 Worker；不要求所有节点预先复制同一个绝对目录。

## 执行可靠性

控制端先持久化任务和资源预留，再派发唯一执行。Worker 在启动子进程前持久化执行标识，事件使用单调序号并在确认后推进游标。重复领取/回传不能重复启动或写入；不同内容重复序号为冲突。

训练在独立子进程执行，GPU 用稳定设备标识限定。指标来自实际训练，日志和结果本地暂存以便断线重传。心跳超时与租约到期只标记待核查并保留占用；控制端重启后恢复记录。进程结束和产物提交分别确认，取消排队任务与停止已启动进程分别处理，重跑创建新任务。

参考 [NVIDIA nvidia-smi](https://docs.nvidia.com/deploy/nvidia-smi/index.html)、[PyTorch 官方版本说明](https://docs.pytorch.org/get-started/previous-versions/)和 [Qwen3-0.6B 模型说明](https://huggingface.co/Qwen/Qwen3-0.6B)。首版实现和测试证据以实施进度记录为准。
