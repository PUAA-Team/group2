# 本轮总体实施计划

## 目标与已授权范围

完成资源、训练和部署的真实流程，所有已实现接口同步接到页面。加入小型预置模型和数据，能从选择版本、配置训练到查看指标、产物、评估和调用服务。外部大模型的智能标注/参数/日志仍保留原一期目标，本轮训练部署不会用模拟结果代替，也不会发送训练样本到外部聊天 API。

2026-10-28 已确认现有 `D:/Anaconda/anzhuang/envs/torch_env` 为 Python 3.12.12、PyTorch 2.5.1+cu121、torchvision 0.20.1+cu121，可在本机 RTX 4060 Laptop GPU 运算，显存 8188 MiB，驱动 566.24。用户批准在 D 盘新建只读复用该环境的独立 LLM 环境，安装 Transformers/PEFT/Accelerate/safetensors/Pillow，以及后端增加 Pillow，并下载 Qwen3-0.6B 公开权重。不得修改原 Conda、系统 PATH 或驱动。

## 实施顺序

| 阶段 | 实际工作 | 必须验收 |
| --- | --- | --- |
| stage7 资源 | 管理员和空间资源页、限时一次性接入码、Worker 包和复制命令、本机快捷接入、注册/审核/心跳/探测/暂停/撤销 | 本机真实 GPU、CPU 和运行时上报，重复注册幂等，权限与失联状态准确 |

每阶段先完成对应数据和 API/SPEC，再编码、迁移空测试库、运行后端/前端/浏览器测试。应用库迁移前备份并展示已验证变更，保留用户现有数据。设计或实际条件改变时先更新实施进度。

## 首版约束

控制端继续为模块化 FastAPI，数据库本机 SQLite，正式 PostgreSQL 单独验证。Worker 主动访问控制端，不开放 Worker 入站端口、不保存 SSH 密码、不扫描网段。首版每节点有限执行槽位，每设备同时只分配一个执行；GPU 显存不作任意切分。只有已有、经授权且运行时匹配的设备可以领取任务。

用户上限继续取组基础上限与个人上限的较小值。GPU 占用及并发执行在派发时核验；当前存储上限的完整扣额需独立完善，不宣称已经完成存储计费或组共享资源预算。原账号没有训练额度时，提供明确的配置入口，不默认为无限额度。

首版预置文本分类线性网络、小型图像 CNN 和 Qwen LoRA。公开基础权重允许下载到 Worker 缓存，上传数据和训练产物由主服务器保存；未来基础模型集中存储及对象存储适配保留清晰接口。镜像提供构建文件和部署命令，未实际构建/推送的镜像不填写为可拉取。
