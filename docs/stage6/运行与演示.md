# 运行与演示

本阶段完成后使用 `http://127.0.0.1:8000/` 操作真实后端。首次管理员通过本机设置页面创建，应用不内置通用密码。

真实界面和 API 同源提供，浏览器操作即可，不必进入接口文档。原型 `http://127.0.0.1:8765/` 独立保留。本阶段没有安装依赖。

## 第一次使用

打开真实入口，填写管理员账号、姓名、工作空间名称和密码，点击“创建并进入”。密码至少 12 位。管理员设置只执行一次；以后进入的是登录页，账号由管理员维护。初始化后会自动登录并建立填写的工作空间。

工作台点击“添加示例资产”，按需选择文本分类、指令微调和图像模型。系统实际登记模型、创建数据集并上传 6 条 CSV 样本、2 条 JSONL 样本；重复添加会复用已有同名示例资产，不覆盖历史版本。模型登记不会下载权重或启动训练。

建议按以下路径演示：

1. 工作台查看真实模型和数据集数量，点击蓝色名称进入详情。
2. 模型仓库新增模型，选择任务和对应模板，填写来源；在详情登记来源版本，并修改名称或说明。
3. 数据集新增数据集，在详情导入 CSV 或 JSONL。可先下载模板，导入后查看实际样本数、大小及状态，点击“样本预览”。再次导入生成 v2，v1 仍可查看。
4. 用户管理切换“用户组”，配置基础授权、显式禁用和资源上限；再新增用户并设置所属组、个人权限或上限。
5. 用户空间添加已有账号，选择编辑者或查看者。退出后用成员账号登录，检查管理菜单及写入按钮是否按权限显示。
6. 操作记录查看当前空间的模型登记、数据导入及成员变更记录。

文本分类 CSV 只含 text、label 两列；空标签允许形成待标注版本，空文本会拒绝。指令 JSONL 每行包含 instruction、output，input 可省略。单文件上限 10 MiB、10000 条样本。图像数据集可登记元信息，归档导入尚未接通。

## 启动与停止

本机服务已在 8000 启动。后续需要重启，在项目根目录执行：

```powershell
& .\backend\scripts\run_backend.ps1 -BackendAction serve -EnableBrowserSetup
```

`-EnableBrowserSetup` 仅在本机首次设置时需要；已有管理员时再次初始化也会被拒绝。默认不开启浏览器初始化，其他环境继续使用部署 CLI。此开关只影响当前子进程，不修改系统环境变量。换端口时还须显式设置 MT_ALLOWED_ORIGINS 中对应的精确来源。

若数据库尚未迁移，先执行脚本的 `-BackendAction migrate`；当前应用库已迁移，不需重置。前台服务 Ctrl+C 停止；后台进程记录在 `D:/model-training-demo/backend-runtime/backend-process.json`。核对 8000 对应命令行后只停止该 Uvicorn，不批量结束 Python，也不停止 8765。不要在已有 8000 服务时重复启动。

源码需保留 backend 与 frontend 兄弟目录结构；运行和上传路径继续使用 D 盘。后续 Linux 部署也需一起复制 `frontend/live`、`frontend/styles` 和 `frontend/js`，本批没有部署 Linux 或 PostgreSQL。原[后端运行说明](../stage5/运行与部署.md)继续适用于环境、迁移、备份和生产准备。
