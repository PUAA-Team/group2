# Stage 19B-3：登录限流与上传产物并发保护

分支：`lx/stage19b-3-login-rate-limit`（基线 `lx/stage19b-2-streaming-data`，本地 b117cf0，未合并 main，未部署，未推送）。

## 完成范围

### 1. 登录限流加账号维度全局滑动计数
- [auth.py](../../backend/src/model_platform/api/auth.py)：登录在原有“账号+IP”单桶限流之外，新增纯账号维度的全局滑动失败计数。同一账号在 15 分钟滑动窗口内累计失败达到 15 次（约为单 IP 阈值 5 次的 3 倍）即锁定整个账号 15 分钟，攻击者轮换 IP 也无法绕过；任一桶被锁定都返回 429 `RATE_LIMITED`。
- 新增 `_record_failure()`：单 IP 桶沿用旧语义（固定计数，锁定期过后归零）；账号桶按滑动窗口处理，窗口过期则计数归零重新起计。登录成功时同时清除两个桶的记录；未知账号同样计入账号桶。
- 配置（[config.py](../../backend/src/model_platform/config.py)）：`login_account_failures = 15`、`login_account_lock_seconds = 900`、`login_account_window_seconds = 900`。
- 迁移 `0015_login_account_rate_limit`：`login_attempts` 表新增 `window_started_at`（当前滑动窗口起始时间），SQLite 与 PostgreSQL 均为简单加列；升降级往返已在 SQLite 上验证通过。

### 2. 上传产物并发保护
- [executions.py](../../backend/src/model_platform/services/executions.py) 的 `store_artifact()`：写存储对象前仍先锁定 Execution 行（`owned_execution(lock=True)`，PostgreSQL 上串行化同一执行的上传）；再用条件更新抢占式声明产物槽位——只有 `artifact_sha256` 仍为空时才能拿到，`rowcount != 1` 时回滚后重读：摘要一致返回幂等成功，不一致返回 409 `ARTIFACT_CONFLICT`。SQLite 下无行锁时该条件更新同样保证并发双传只有一个能拿到槽位，不会覆盖已落盘的产物。
- [file_storage.py](../../backend/src/model_platform/services/file_storage.py) 的 `write_atomic()` 新增可选参数 `staged_name`：`store_artifact()` 每次上传用唯一临时文件名 `{execution.id}.{uuid}.zip`，写盘与提交之间不与并发上传共用暂存文件；不指定时沿用旧的 `.upload` 后缀，其他调用方不受影响。
- 槽位声明在扣费与写盘之前：抢到槽位的才扣费、写盘、提交；没抢到的不扣费、不写盘；写盘或提交失败时回滚并删除已落盘文件（与原有逻辑一致）。

### 3. 说明与边界
- 本阶段无新增 API 接口，OpenAPI 同步导出到 [openapi.json](./openapi.json)（144 个路径，与上一阶段一致）。
- 账号桶的锁定期与窗口均为固定配置，未做管理端可配；如需按账号风险分级调整阈值，需后续接入管理端设置。
