## 数据库与账号

本机 SQLite，正式部署 PostgreSQL。迁移和初始化是显式操作，程序启动不重置数据。当前 D 盘应用库已迁移到 `0001_m1`，管理员由使用者在首次设置或 CLI 创建。测试账号仅存在于独立测试目录，无法登录应用库。

下面命令在项目根目录的 PowerShell 执行。脚本只设置自身进程及子进程的运行变量，退出后恢复原值。

```powershell
# 首次安装或升级时执行；已有数据库先备份。
& .\backend\scripts\run_backend.ps1 -BackendAction migrate

# 前台启动，Ctrl+C 停止；已有后台服务占用 8000 时不要重复启动。
& .\backend\scripts\run_backend.ps1 -BackendAction serve
```

首次管理员由部署者设置自己的密码，至少 12 位，输入不回显；没有通用默认密码。另开一个 PowerShell，在项目根目录运行：

```powershell
$env:PYTHONPATH = Join-Path (Get-Location) 'backend/src'
$env:MT_RUNTIME_DIR = 'D:/model-training-demo/backend-runtime'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:PYTHONIOENCODING = 'utf-8'
& 'D:/model-training-demo/backend-runtime/.venv/Scripts/python.exe' -B -m model_platform.cli bootstrap-admin --account admin --display-name '平台管理员'
```

初始化只允许执行一次。后续账号和用户组通过管理 API 创建。不要把密码写在命令参数、仓库、截图或日志中。`--password-stdin` 供受控自动化使用；交互操作优先使用默认隐藏输入。

生产首次上线前需要确认 HTTPS、Cookie Secure、允许的浏览器来源、数据库权限、迁移、备份、日志目录和文件存储。SQLite 本机验证不代替 PostgreSQL 的事务、行锁和并发集成测试。

## 备份与恢复

运行前后的设计备份保存在运行根目录 `backups`。业务备份需同时包含数据库和其引用文件；SQLite 运行中使用数据库备份接口或先停止服务，不能只复制不一致的主文件。正式 PostgreSQL 使用其备份工具，并核对文件清单和摘要。

恢复先在新目录验证，不覆盖正在运行的数据；迁移前保留可恢复快照。回滚应用代码不代表数据库自动回退，涉及结构变化时单独评估恢复方式。

## 接口联调

操作界面：`http://127.0.0.1:8000/`。开发接口文档：`http://127.0.0.1:8000/docs`，原始契约：`http://127.0.0.1:8000/openapi.json`。仓库保留[运行应用导出的 OpenAPI](./openapi.json)，当前包含 33 个 API 操作的输入、输出和 Cookie 认证定义。

初始化管理员后，在接口文档执行 `POST /api/v1/auth/login`，JSON 使用 account、password。浏览器接收 HttpOnly Cookie，复制响应中的 csrf_token；后续状态修改在 X-CSRF-Token 参数中传入该值。GET session 可以重新获取同会话 token。不要把会话 Cookie 手工存到 localStorage。

创建顺序为：用户组及用户 → 工作空间 → 成员角色 → 模型/数据集 → 资产版本。PATCH 元信息还要传 If-Match，例如 `"1"`；上传数据版本会递增数据集 revision，修改前应重新读取。CSV 模板为 text、label 两列；JSONL 为 instruction、input、output，input 可省略。单文件上限 10 MiB、10000 个样本；前 10 个样本默认可预览，最多 50 个。

页面与 API 使用同一种主机写法，例如都用 127.0.0.1；当前真实界面由 8000 同源提供。现有 8765 页面继续使用原型数据，仅作对照，不自动切换。

## 测试、导出与停止

```powershell
& .\backend\scripts\run_backend.ps1 -BackendAction test
```

测试脚本每次创建一个 D 盘随机独立目录，并输出位置，JUnit 报告为该目录的 report.xml；不使用应用库。当前结果 43 项通过。Starlette 对 HTTPX 测试适配器有一项弃用提示，仍可运行；本批未额外安装 HTTPX2。前端当前 73 项测试使用 Node `--test --test-isolation=none` 通过；沙箱下默认子进程模式会触发 EPERM。

重新导出接口前，按管理员初始化命令设置当前进程的 PYTHONPATH，然后执行：

```powershell
& 'D:/model-training-demo/backend-runtime/.venv/Scripts/python.exe' -B -m model_platform.cli export-openapi --output './docs/stage5/openapi.json'
```

本次后台启动记录位于 `D:/model-training-demo/backend-runtime/backend-process.json`，日志在 logs。停止后台服务前先核对该记录、8000 监听 PID 和进程命令行；只停止对应 Uvicorn 进程，不批量结束 Python，也不影响 8765。前台启动直接 Ctrl+C。进程号每次启动会变化。

## Linux 与 PostgreSQL 部署准备

本批没有登录云服务器或部署 PostgreSQL。后续在已准备好的 Linux、Python 3.12 和专用 PostgreSQL 数据库上执行，先创建应用自己的可写运行目录和独立环境。例如源码 backend 放在 `/srv/model-platform/backend`，运行数据放在 `/srv/model-platform/runtime`：

```bash
python3.12 -m venv /srv/model-platform/runtime/.venv
/srv/model-platform/runtime/.venv/bin/python -m pip install -r /srv/model-platform/backend/requirements.lock.txt
export PYTHONPATH=/srv/model-platform/backend/src
export MT_RUNTIME_DIR=/srv/model-platform/runtime
export PYTHONDONTWRITEBYTECODE=1
export TMPDIR=/srv/model-platform/runtime/temp
export MT_SECURE_COOKIE=1
export MT_ALLOWED_ORIGINS=https://training.example.internal
# 输入专用连接串，形如 postgresql+psycopg://...，避免写进 shell 历史。
read -rs -p 'Database URL: ' MT_DATABASE_URL
export MT_DATABASE_URL
/srv/model-platform/runtime/.venv/bin/python -B -m model_platform.cli migrate
/srv/model-platform/runtime/.venv/bin/python -B -m model_platform.cli bootstrap-admin --account admin --display-name '平台管理员'
/srv/model-platform/runtime/.venv/bin/python -B -m uvicorn model_platform.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

上述为后续部署命令，域名和目录由部署者按实际环境替换，temp 需事先创建。源码保留 backend 与 frontend 兄弟目录，后者需包含 live/styles/js。生产不启用 MT_ALLOW_BROWSER_SETUP，首次账号仍用 CLI。再由反向代理提供 HTTPS，使用专用系统用户和受限文件权限，完成 PostgreSQL 并发、持久化、备份恢复及 Cookie/CORS 验收后才开放团队访问。当前锁文件来自 Windows，本批仅验证 Windows 安装；Linux 安装和数据库实测属于后续验收。
